# 계정 공통 6자리 PIN · 2026-11-08

## 사용자 흐름
- 이메일·Google 가입 모두 인증된 로그인 후 PIN 설정을 가입 마지막 단계로 제공한다. 이메일 확인 전 PIN을 브라우저나 사용자 메타데이터에 임시 저장하지 않는다.
- PIN 미설정 회원은 이메일·Google 로그인 또는 인증된 가입이 실제 성공한 직후 필수 모달로 설정한다. 이미 로그인한 세션은 기존 화면을 열거나 새로고침·탭 복귀해도 모달을 자동 표시하지 않는다. 새 로그인에서 시작된 설정은 완료 또는 로그아웃까지 유지하며 이메일 복구 화면은 예외로 둔다.
- 내정보 수정의 현재 비밀번호 재입력을 PIN 확인으로 교체한다. 기존 로그인 비밀번호와 소셜 로그인 방식은 유지한다.
- PIN 분실 시 로그인한 본인의 가입 이메일로 Supabase 복구 링크를 전송한다. 이메일 링크 확인 후 10분 이내에만 새 PIN을 저장한다. 이메일 기본 서식의 제목에 비밀번호 재설정이 표시될 수 있음을 안내하고, 실제로는 PIN만 바꾼다.

## 서버 보호
- 운영 프로젝트 `pt-career-web`에 `20261107235552_account_security_pin.sql` 적용 완료. 공식 CLI로 생성한 파일의 시각을 운영 이력과 맞췄다. 기존 회원 PIN을 임의 생성하거나 로그인 비밀번호를 변경하지 않는다.
- PIN은 비공개 `pin_private` 스키마의 bcrypt(cost 12) 해시로 보관한다. PIN·해시·실패 횟수 원문을 공개 프로필, 사용자 메타데이터, 응답, 로그에 넣지 않는다.
- 직접 테이블 읽기/쓰기를 차단하며 RLS 기본 거부를 유지한다. 공개 RPC는 권한 상승 없이 비공개 함수로 위임하고 익명 실행 권한을 거부한다. 비공개 함수는 실제 사용자·활성 로그인 세션·확인된 이메일을 검사한다.
- 검증 권한은 계정 전체가 아닌 해당 세션에만 10분간 부여한다. 로그아웃으로 삭제된 세션 및 다른 계정/세션의 재사용은 거부한다.
- 계정 단위 행 잠금으로 동시 입력도 실패 횟수를 공유한다. PIN 5회 연속 오입력 시 15분 잠금. 잠금 중 올바른 PIN도 거부하고, 만료 후 또는 이메일 재설정 후 해제한다.
- 최초 설정은 이미 설정된 PIN을 덮어쓰지 못한다. 재설정은 Supabase가 서명한 최근 `recovery` 인증 시각을 검사하며, PIN 변경 시각 이후의 확인만 허용한다. 재설정 후 모든 세션의 내정보 확인 권한을 회수하고 같은 복구 인증의 재사용도 막는다.
- 내정보 페이지는 서버에서 검증 상태를 확인한 뒤에만 기존 개인정보를 조회·렌더링한다. 기존 화면의 정보 저장·집주소 보관 기능은 여전히 배치 미리보기이며 이번 PIN 작업에서 새로 연결한 기능은 아니다.

## 검증과 한계
- 새 입력값·모달·이메일 목적지·서버 오류 차단 자동 테스트 11개, 전체 회귀 45개 묶음/275개 및 TypeScript 검사를 통과했다. 최종 모달 닫힘 방지·통신 실패 처리 보완 후 해당 11개와 TypeScript를 다시 통과했다. 기존 별도 DB/인증 환경 전용 테스트 묶음은 실행 대상에서 제외했다.
- `supabase/tests/account_security_pin.sql`: 가짜 사용자·세션을 생성해 설정/변경 거부, 올바른 PIN, 오입력 잠금·만료, 세션 분리·만료, 테이블 접근 거부, 이메일 재설정·재사용 거부, 익명·타인·폐기 세션 거부를 확인했다. 트랜잭션 전체 롤백 후 임시 사용자가 0명임을 확인했다. 실제 회원의 PIN은 설정하거나 수정하지 않았다.
- 브라우저에서 기존 로그인 회원의 필수 설정 팝업과 Esc 차단을 확인했다. 사용자가 직접 PIN을 입력할 수 있도록 빈 입력창을 남긴다.
- 최초 배포 검증 시 실제 가입 메일 수신·Google 신규 가입·실제 이메일 링크 재설정 완료는 미확인이었다. 복구 메일의 후속 실사용 결과는 아래 2026-11-08 점검을 참고한다. DB 검증은 서명된 인증 컨텍스트를 가짜 값으로 모사한 테스트이며 실제 메일 전송 완료를 의미하지 않는다.
- Supabase 보안 점검에서 신규 PIN 공개 RPC의 definer 실행 경고는 없었다. 비공개 PIN 테이블의 정책 없음 INFO는 직접 접근 기본 거부 의도다. 기존 공개 함수/이메일 OTP 만료/유출 비밀번호 보호 설정의 경고는 이번에 변경하지 않았다. 기존 보안 현황 P0-10도 해결된 것으로 보지 않는다.
- 웹 코드는 미리보기에만 적용했다. 운영 DB 준비는 완료했으나 웹 배포 전까지 운영 사이트의 기존 화면은 유지된다. 롤백 시 이전 웹 코드로 복구하고 비공개 PIN 저장소는 보존한다. PIN 기록 삭제나 서버키 교체는 필요하지 않다.

## 로그인 직후로 설정 시점 조정 · 2026-11-08
- 기존 로그인 상태를 기준으로 즉시 표시하던 동작과 전역 `SIGNED_IN` 구독을 제거했다. SDK의 로그인 알림은 탭 복귀에도 발생할 수 있어 새 로그인 판정에 사용하지 않는다.
- 이메일 로그인 성공·즉시 인증된 가입·OAuth/이메일 가입 확인 콜백에서만 설정 시작을 표시한다. HttpOnly 쿠키는 서명 검증된 로그인 세션의 지문과 비교하고 다른 세션으로 승계하지 않는다. 이 쿠키는 표시 시점 전용이며 내정보 접근 권한이나 PIN 검증을 대신하지 않는다. PIN 저장 후 삭제한다.
- 복구 링크 콜백은 새 설정을 시작하지 않는다. PIN·비밀번호 복구 화면은 설정 팝업과 별도로 진행한다. 콜백 예외는 원문 대신 통제된 오류 분류만 기록한다.
- 현재 로그인 계정에서 미리보기의 ‘확인 링크 받기’를 한 번 눌러 실제 Supabase 메일 요청의 성공 응답을 확인했다. 메일 도착·같은 브라우저의 확인 링크 이동·새 PIN 저장은 요청 성공과 구분하여 확인한다. 사용자 PIN을 대신 정하거나 이메일 확인 링크를 로그/채팅에 남기지 않는다.
- 변경 후 전체 48개 묶음/290개 테스트와 TypeScript 검사를 통과했다. 기존 세션 무표시, 세션별 시작 표식, PIN 설정 회원 무표시, 이메일 로그인·가입 및 OAuth 콜백의 시작 연결, 이메일 복구 콜백 예외를 검증했다. 기존 별도 DB/인증 환경 전용 테스트 제외 범위는 유지한다.
- 미리보기 검증은 웹 배포·DB 변경 없이 수행했다. 이번 수정에는 운영 DB 변경이 필요하지 않으며 최종 배포 결과는 현황판에 별도로 기록한다. 테스트 요청만으로 실제 전달 또는 PIN 변경 완료로 기록하지 않는다.

## 복구 메일 수신 점검 · 2026-11-08
- 실제 요청 한 번의 `/auth/v1/recover` 응답 200과 `recovery` 유형의 `mail.send` 이벤트를 확인했다. 발신 도메인은 `mail.app.supabase.io`다. 이는 발송 요청 기록이며 받은편지함 도착 확인은 아니다. 원문 이메일·인증 링크·토큰·요청 헤더는 출력하거나 문서에 저장하지 않는다.
- 사용자가 처음에는 메일 미수신을 보고했으나, 서버 기록의 마스킹된 수신 주소를 확인한 뒤 다른 메일함을 확인했다고 답했다. 이후 실제 수신 대상에서 메일 도착과 새 PIN 설정 화면 진입을 확인했다고 답했다. 중복 발송이나 SMTP 설정 변경은 하지 않았다.
- 메일 수신·링크 진입에 이어 ‘새 PIN’과 ‘PIN 확인’ 입력칸 두 개가 보인다는 사용자 확인을 받았다. 연결된 기존 미리보기 탭은 발송 요청 화면이어서 재설정 화면은 도구로 직접 관찰한 결과와 구분한다. 인증 서버에는 확인 링크 경로의 303 응답도 있었으나, 이 기록만으로 PIN 재설정 완료를 판정하지 않는다.
- 메일 수신 → 확인 링크 → 새 PIN 입력 화면은 사용자 실사용 확인 완료다. 실제 새 PIN 저장과 저장 후 접근은 아직 검증하지 않았다. PIN은 사용자가 직접 입력·제출하며 도구로 수집하거나 대신 설정하지 않는다. 메일 도착 지연·반송 장애로 확정하지 않으며 발송 서비스도 변경하지 않는다.
- 요청 성공 안내를 ‘메일 발송을 요청했습니다’로 바꾸고, 본인에게만 일부 가린 수신 주소를 표시한다. 서비스 제공자의 오류 원문이나 전체 이메일은 응답에 포함하지 않는다.
- 메일 안내 보완 후 PIN 관련 5개 묶음/29개 테스트와 TypeScript 검사를 통과했다. 앞선 전체 48개 묶음/290개 검사와 구분한다.
- 배포 전 최종 전체 48개 묶음/293개 테스트를 통과했다. 별도 DB·인증 환경 전용 기존 테스트 제외 범위는 유지한다. 실제 회원의 PIN 저장·변경과 신규 이메일/Google 가입 실사용 검증은 미완료다.
