# 프로필 게시·증빙 일괄 심사 미리보기

2026-11-08 초기 미리보기 기록이다. 이후 사용자가 실제 서버 연결·검증·커밋·병합·배포를 승인했고 운영 DB 연결을 완료했다. 릴리스 범위와 서버 검증은 `docs/report/PROFILE_BATCH_REVIEW_RELEASE_2026-11-08.md`를 따른다.

## 화면과 동작

- 프로필로 가져온 다모아 활동의 자료를 해당 항목에 자동 연결한다. 다른 활동의 자료까지 자동 선택하지는 않는다. 기존에 저장한 선택과 명시적으로 제외한 자료는 존중한다.
- 공개 전 확인의 우측에는 `프로필 게시`를 주 동작으로 두고 요청할 새 증빙 건수를 표시한다. 연결 자료와 심사 내역은 접어서 제공하며 필요할 때만 확인한다.
- 게시 버튼을 누르면 제출 건수·관리자 확인 범위·파일 공개 조건을 안내하는 팝업을 연다. 매번 동의 체크 후 `동의하고 게시`를 눌러야 기존 게시 처리를 실행한다. 동의 전에는 파일 업로드·심사 접수·게시를 실행하지 않으며 취소 후 다시 열면 체크를 초기화한다. 실패 시 팝업에서 오류를 안내하고, 신규 제출 대상이 없으면 프로필만 게시됨을 안내한다.
- 항목의 `+`에서 `증빙자료 확인`을 열어 자료 선택·이미지/PDF 미리보기·파일 공개 여부를 바꾸고 `반영`한다. 개별 첨부 저장·심사 요청 버튼은 제거한다.
- 각 항목의 +/− 앞에 배경 없는 회색 클립과 연결 파일 개수를 표시한다. 자료가 없으면 생략하며 클릭하면 같은 확인 창에서 연결된 파일을 우선 미리 본다. 선택을 반영하면 개수도 갱신된다. 실제 공개 화면에는 편집용 클립을 추가하지 않는다.
- 자료 선택 변경은 게시할 때 적용한다. 프로필 내용 저장과 별개로 서버 초안에 저장되는 기능은 아니며, 게시 전 새로고침하면 이 임시 선택은 초기화된다.
- 서류는 기본 비공개다. 파일 공개를 명시적으로 선택하더라도 기존 관리자 승인·현재 공개 프로필 포함 조건과 워터마크 제공 규칙을 유지한다.
- 변경 없는 승인·심사 중·반려 내역은 재요청하지 않는다. 신규 자료와 변경한 자료·내용은 새 심사 대상으로 계산한다. 증빙 없는 항목과 공개에서 제외하거나 표시 내용을 모두 숨긴 항목은 요청하지 않는다.
- 자료를 불러오지 못하면 게시를 막고 다시 불러오기를 제공한다. 프로필 내용이 변경됐으면 기존 저장 절차를 먼저 거친다.

## 서버 연결 준비 상태

서버 액션은 게시와 심사 요청을 `publish_profile_with_reviews` 한 번으로 전달하도록 작성했다. 준비한 SQL은 본인 소유·저장 내용 일치·자료 소유/업로드 완료·항목 포함 여부·기존 심사 시점 등을 확인하며, 요청 또는 게시 실패 시 같은 트랜잭션에서 모두 취소하도록 구성했다. 자료 파일 업로드는 이 DB 트랜잭션보다 먼저 수행되므로 실패한 업로드 정리 기능은 기존 경로를 따른다.

`supabase/migrations/20261108082152_profile_publish_with_reviews.sql`을 운영 DB에 적용했다. CLI로 만든 로컬 파일명은 서버가 기록한 실제 적용 버전에 맞췄다. 본인 권한·자료 연결·심사와 게시의 원자성은 실제 DB에서 롤백 방식으로 검증했다. 새 함수 없이 기존 게시만 수행하는 우회 동작은 제공하지 않는다.

## 미리보기

- 주소: `http://localhost:3002/preview/profile-publish`
- 개발 환경에서만 열리는 페이지다. 일반 프로필 관리 화면의 동일 컴포넌트를 예시 자료로 구동한다.
- 기본 예시는 연결 자료 4개, 신규 요청 2건, 기존 승인 1건, 심사 중 1건이다. 자료 없는 활동도 포함한다.
- 예시 게시 버튼은 화면 안에서만 상태를 바꾼다. 실제 프로필 게시·파일 업로드·심사 접수는 하지 않는다. 사용자의 실제 서류 대신 개인정보 없는 합성 이미지를 사용한다.
