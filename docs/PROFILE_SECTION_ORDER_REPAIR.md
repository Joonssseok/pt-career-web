# 로그인 이동·공개 프로필 순서 수정

확인일: 2026-11-08 KST

- 이메일·Google 로그인과 로그인 콜백의 기본 목적지를 `/home`으로 맞췄다. 보호된 화면에서 요청한 안전한 내부 복귀 주소와 PIN/비밀번호 복구 목적지는 유지한다. 기존 PIN 설정 시작 절차도 유지한다.
- 공유 설정의 게시 전·게시 후 화면에서 ‘QR코드는 정식 도메인 연결 후 제공할 예정이에요.’ 문구를 제거했다. 연결된 접근성 설명 참조도 제거했으며, 정식 도메인 확정 전 QR 발급/복사 보류 정책은 유지한다.

## 순서 오류 원인과 수정

1. 대상 프로필의 초안·공개본에는 소개 다음에 다모아 학력을 놓은 순서가 동일하게 저장돼 있었다. 공개 조회 함수의 중첩 쿼리가 저장된 섹션 키 대신 활동의 `value`를 비교해 다모아 분류 순서만 빠뜨렸다. 가짜 입력에서도 같은 누락을 재현했다.
2. 공개 페이지의 서버 렌더링에서 섹션 카드가 먼저 펼쳐져, 클라이언트 정렬에 필요한 키와 제목이 사라졌다. 실제 운영 DOM에서도 모든 섹션 키가 없는 상태를 확인했다. 공통 섹션 카드를 클라이언트 경계로 유지하고 갤러리도 이 카드를 재사용해 편집/공개 화면에 같은 정렬 정보를 전달한다. 카드 디자인은 유지한다.
3. 공통 이력과 다모아 항목을 한 카드로 묶을 때 분류 키가 달라져도 저장된 위치를 따라가도록 맞췄다. 항목 내부의 정렬 범위, 전문 분야 상단 고정, 상세 이미지 최하단은 유지한다.

## 서버 적용 범위

- 기존에 승인된 개인별 프로필 순서 처리 범위에서 `profile_version_public_order`의 쿼리 별칭만 보완했다. 적용 이력: `20261108053207_preserve_public_activity_section_order`.
- 실제 회원의 프로필·다모아 원본·공개 여부를 저장/변환하거나 게시하지 않았다. 기존 함수의 권한과 invoker 속성은 동일함을 확인했다.
- 실제 변경 전에 함수 수정과 가짜 자료 검사를 한 트랜잭션 안에서 실행하고 롤백했다. 원래 함수 정의와 권한이 복구됨을 확인한 후 적용했다.
- 공개된 활동의 분류만 순서 정보에 남으며 비공개 분류·항목 키는 계속 제거된다. 합성 입력의 순서 보존·비공개 키 제거·빈 입력 검사 및 보안 점검을 통과했다. 새 순서 함수 경고는 없으며 기존 보안 후속 조치의 완료를 뜻하지 않는다.

## 검증과 배포 상태

- 수정 전 실패한 로그인 이동 및 분류 키 전환 테스트 8개가 수정 후 통과했다.
- 브라우저의 실제 공개 페이지 렌더링 방식을 사용한 로컬 미리보기에서 전문 분야 → 소개 → 학력 → 자격/면허 → 교육 이수 → 경력 → 협회·전문단체 활동 순서를 확인했다.
- 전체 자동 테스트 48개 묶음/301개와 TypeScript 검사를 통과했다. 기존 별도 DB·인증 환경 전용 테스트 제외 범위는 유지한다.
- 서버 함수 보완은 적용했다. 웹 코드는 2026-11-08 사용자 승인 배포에 포함한다. 실제 운영 반영 결과와 커밋은 현황판에 기록한다. 실제 이메일/Google 재로그인은 대신 실행하지 않았다.

## 학력 순서 재신고 확인 (2026-11-08)

- 다시 저장한 대상 프로필의 초안과 공개본 모두 `introduction` 바로 다음에 `activity:학력`이 유지됨을 재확인했다. 저장 누락이나 초안/공개본의 순서 차이가 원인은 아니다.
- 재신고 확인 당시 운영 별칭은 PR #138의 `d41c1e32092a4e5218e54ee43d9231f146884025` 배포를 제공했다. 해당 배포에는 위 웹 렌더링 수정이 없어 공개 화면에서 학력이 끝에 표시됐다.
- 동일한 서버 자료를 사용하는 수정 코드의 로컬 공개 페이지에서는 전문 분야 → 소개 → 학력 → 자격/면허 → 교육 이수 → 경력 → 협회·전문단체 활동 순서가 표시됨을 브라우저로 재확인했다. 실제 회원 자료를 다시 저장하거나 게시하지 않았다.
- 배포 직전 전체 자동 테스트 49개 묶음/307개와 TypeScript 검사를 통과했다. 기존 별도 DB·인증 환경 전용 테스트 제외 범위를 유지한다.
