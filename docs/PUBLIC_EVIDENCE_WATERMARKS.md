# 공개용 사본의 두 가지 표식

2026-11-04 · 사용자가 확정한 범위

## 표시 처리

- 소유자가 로그인해서 열거나 내려받는 원본에는 표시를 추가하지 않는다. 개인적으로 다른 AI에서 활용할 수 있게 그대로 제공한다. 심사 관리자도 원본을 확인한다.
- 타인에게 제공하는 공개용 사본에만 눈에 보이는 PT Career 워터마크와 눈에 보이지 않는 문서별 식별 표식을 함께 넣는다.
- 관리자 역할은 기존 공개 전 점검에서 개인정보 노출과 해당 항목에 맞는 자료인지 확인하는 것이다. 새로운 서류 진위 인증·AI 인증·도용 판단·조사·추적 관리 기능은 추가하지 않는다.
- 숨은 코드에는 이름·연락처·주민등록번호·방문자 정보가 없다. 공개 서류의 식별값으로 만든 불투명한 사본 코드를 사용한다. 외부 AI나 처리 업체에 서류를 보내지 않는다.

## 형식과 한계

- JPG·PNG·WebP 입력의 공개 사본은 PNG다. 가시 워터마크를 그린 뒤 픽셀의 하위 비트에 숨은 코드를 분산 삽입한다. 파일 속성 정보를 제거해도 픽셀이 유지되면 표식이 남는다.
- PDF에는 모든 페이지에 가시 워터마크와 화면에 그려지지 않는 텍스트 표식을 넣는다. 별도의 인증 조회 주소나 AI 지시문을 만들지 않는다. 원래 양식의 표시 내용은 보존한다.
- 이 표식은 복제 파일에 흔적을 남기는 처리이며, 제거 방지·무단 사용 차단·캡처·재압축·크기 변경·AI 편집 후의 유지나 검출을 보장하지 않는다. 강한 편집 내구성이 필요해지면 별도의 전문 디지털 워터마크 방식이 필요하다.
- 암호화·50페이지 초과 PDF, 보존할 수 없는 동적 양식·주석, 4천만 픽셀 초과 이미지 등 지원 범위를 벗어나면 원본을 대신 공개하지 않고 오류로 종료한다. 이는 안전한 파일 처리 조건이며 서류 종류나 진위의 판정이 아니다.

## 공개 및 보관

- 기존 공개 선택·관리자 점검·현재 대표 공개 프로필 포함 조건은 유지한다. 공개 상태는 사본 처리 후 다시 확인한다.
- 원본의 익명·타 회원 직접 다운로드를 막는 저장소 접근 제한을 적용했다. 새 서버 전용 저장소 자격을 만들거나 비밀값을 출력하지 않는다. 기존 서버 자격은 공개 조건 확인 뒤 사본 처리에만 사용한다.
- 원본·다모아 용량을 변경하지 않는다. 사본을 별도 영구 저장하지 않으며 내려받을 때 생성한다. 다운로드 시 변환 처리 비용이 발생한다.

## 적용 및 검증 기록

- 사용자의 구체적인 서버 변경 승인 후 운영 DB에 `20261104083824_public_evidence_watermarks`, `20261104084032_evidence_original_policy_guard`를 적용했다.
- TypeScript 통과, 38개 테스트 묶음·227개 테스트 통과. 합성 이미지의 파일 속성 제거 후 숨은 표식 추출, 합성 PDF 3페이지의 속성 제거 후 비가시 텍스트 추출과 화면 표시 보존을 확인했다.
- 운영 DB에서 익명·다른 회원의 원본 접근 차단, 본인·관리자의 원본 접근, 기존 공개 조건을 충족한 사본 소스 조회, 항목 제외 시 차단을 검증했다. 임시 검증 변경은 모두 롤백했다. 관리자 판별 함수의 익명 실행 권한을 늘리지 않았으며 다른 프로필 이미지의 조회도 유지된다.
- 적용 전후 프로필·프로필 버전·다모아 파일·심사 기록·원본 저장소 메타데이터가 동일함을 확인했다. 기존 자료 삭제·자동 공개·공개 설정 변경은 없다.
- 미리보기에서 없는 자료 요청은 캐시 없이 404, 기존 공개 프로필은 200으로 응답했다. 실제 공개 증빙파일은 현재 0개이므로 실제 회원 자료의 공개 다운로드 성공 검증은 수행하지 않았다. 가시·비가시 표식과 사본 응답은 합성 파일 및 자동 테스트로 검증했다.
- 합성 예시는 `C:/Users/User/OneDrive/Desktop/임시/evidence-watermark-preview-v2/`에 있다. 웹코드의 배포 커밋·배포 결과는 개발 현황판의 이번 작업 기록으로 추적한다.
