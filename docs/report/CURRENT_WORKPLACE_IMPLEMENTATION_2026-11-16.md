# 다모아 경력에서 현재 근무지 선택

2026-11-16 KST. 인계된 지도 코드를 현재 제품 코드에 통합했다. 기존 직군·전문분야 접이식 선택 화면은 PR #151로 별도 배포했다.

## 구현

- 다모아 경력의 자세한 기록에 근무지 주소·기관 전화·기관 홈페이지를 추가한다. 공식 기관 정보만 입력하도록 안내한다.
- 프로필 작성의 기본정보에서 본인 다모아 경력 하나를 선택한다. 기관명·공식 주소·전화·홈페이지의 사본만 이 프로필 내용에 담는다. 원본 업무·메모·파일 전체를 복사하거나 자동 공개하지 않는다.
- 다모아를 수정한 뒤에는 다시 가져오기로 이 프로필의 사본을 갱신한다. 원본 변경이 이미 게시한 주소를 자동으로 바꾸지 않는다.
- 기존 프로필의 새 필드가 없으면 종전 표시를 유지한다. 명시적으로 선택하지 않음으로 바꾸거나 공개 전 확인에서 숨기면 해당 기관 정보는 제공하지 않는다. 주요 활동 지역은 별도로 유지한다.
- 공개 전 확인과 실제 공개 프로필은 같은 기관 필드를 사용한다. 근무기관 정보는 본인 입력이라고 표시한다.
- 지도 보기를 직접 누를 때만 SDK·주소 변환을 요청한다. 키·인증·주소 변환에 실패하면 외부 지도 링크를 유지한다. 좌표 저장이나 Client Secret 사용은 하지 않는다. 개인정보처리방침 개정 초안에도 이 외부 요청을 설명한다.

## 운영 DB 변경과 보존 확인

사용자가 기관명·공식 주소·전화·홈페이지 저장 및 게시 시 공개하는 구체적 범위를 승인한 뒤 `profile_current_workplace`를 적용했다.

- 기존 `profile_version_content_valid`와 `profile_version_visible_expert`만 추가형으로 확장했다. 테이블·역할·소유자 검증·기본 공개 상태는 변경하지 않았다.
- 순수 함수 검증: 기존 형식, 새 형식, 명시적 제거, 잘못된 값·미허용 필드·위험한 URL 거부, 숨김과 활동 지역, 원본 식별자 비노출을 확인했다.
- 저장 → 게시·일괄 심사 함수 → 공개 조회 → 숨김 후 재게시 경로는 단일 트랜잭션에서 확인하고 전부 롤백했다. 실제 회원의 게시 상태를 변경한 결과로 남기지 않았다.
- 변경 전후 및 롤백 검증 후 기존 공개 응답의 비교 지문이 같았다. 개별 회원정보와 원문은 기록하지 않았다.
- 되돌림: 먼저 이전 앱으로 되돌린 뒤 `CURRENT_WORKPLACE_ROLLBACK.sql`로 이전 공개 표시 함수만 복원한다. 확장된 형식 검증은 유지해 이미 저장한 새 사본의 편집을 막지 않는다. 새 키를 포함한 저장 내용이 없음을 확인한 경우에만 이전 검증 함수까지 복원할 수 있다.

## 검증과 한계

- 일반 자동 테스트 65개 묶음 415개 항목, TypeScript 및 변경 형식 검사 통과. 별도 DB 접속이 필요한 기존 통합 테스트 6개 묶음은 제외했다.
- 지도 SDK와 주소 변환은 가짜 공개 키·SDK로 클릭 전 외부 요청 없음, 지도·마커 생성, 변환 실패 시 대체 링크를 검증했다.
- 예시 경력 선택 → 서버에 쓰지 않는 가상 저장 → 공개 전 확인의 기관명·주소·홈페이지 표시를 브라우저에서 확인했다. 모바일 360px 요청 폭에서 가로 넘침 없음.
- Vercel의 지도 공개 키와 서버 비밀값은 Production·Preview 대상의 존재만 확인했다. 값은 조회·기록하지 않았다.
- 실제 네이버 지도 타일·마커가 그려지는 모습과 네이버 콘솔 허용 URL·사용 한도는 아직 확인하지 않았다. 로컬에는 지도 키가 없어 링크 대체 표시를 확인했다.
- 실제 회원이 새 기관 정보를 저장·게시하는 브라우저 흐름과 모바일 실기기 검증은 별도 확인 대상이다. 운영 배포 결과는 해당 PR과 현황판의 배포 기록으로 확인한다.

## 인계서의 후속 과제

- 새 도메인의 Google·네이버·이메일/PIN 전체 경로를 따로 점검한다. 네이버 버튼 진입과 사용자의 정상 확인은 있었으므로 새 도메인 인증이 전부 미설정이라고 단정하지 않는다. 이번 작업에서는 인증 설정을 바꾸지 않았다.
- 공유 링크 고정 주소 교체와 옛 주소 자동 이동은 별도 작업으로 남긴다. 기존 주소는 유지한다.
- 지도 좌표 저장의 이용 조건과 여러 기관을 한 지도에 모으는 기능은 미착수다. 외부 고객센터에 문의를 보내거나 이용 한도를 변경하지 않았다.
- QR의 도메인 확정 선행 조건은 충족됐지만 영구 공유 주소 결정과 경로 검증은 남아 있다.
- 현황판 기록에는 공개 가능한 구현·검증 요약만 담는다. 기존 인증 전달 경로 문제로 온라인 현황판 게시가 완료되지 않았다면 로컬 기록과 구분한다.

## 추가 검증 — 지도 연결 복구 (2026-11-16, 앱 코드 미배포)

- 로컬 공개 지도 키 연결 누락을 수정했다. 공개 Client ID만 로컬 비추적 환경설정에 연결했고 Client Secret은 추가하지 않았다. 값은 기록하지 않는다.
- 콘솔에서 Dynamic Map·Geocoding·Reverse Geocoding·Static Map이 이미 활성화된 것을 확인했다. 서비스 선택·키·이용 한도·운영 도메인은 변경하지 않았다.
- 사용자에게 변경안을 제시하고 저장 직전 승인받아 개발용 Web 서비스 URL만 http://localhost:3000에서 http://localhost로 수정했다. 공식 안내는 포트와 경로를 제외한 호스트만 등록하도록 한다.
- 실제 공개 프로필 경로의 로컬 미리보기에서 네이버 지도 타일과 위치 마커가 표시되는 것을 눈으로 확인했다. 이제 이전 보고서의 실제 지도 미확인 항목 중 로컬 표시 부분은 확인됐다. 운영에서 새 코드 표시와 모바일 실기기는 별도 확인 대상이다.
- 주소 변환 오류 시 응답이 없을 수 있는 경우의 예외를 수정했다. 공개 프로필은 주소 공개 시 자동 지도 로딩, 편집 미리보기는 직접 지도 보기 선택을 유지한다. 관련 18개 테스트와 타입 검사 통과.
- 이 추가 앱 코드 수정은 아직 커밋·배포하지 않았다. 콘솔 허용 주소 변경 적용과 앱 배포를 구분한다.
- 기준: https://guide.ncloud-docs.com/docs/application-maps-troubleshoot

## 후속 배포 준비 — 다모아·경력 입력·공개 지도 정리

- 다모아 표시 분류를 경력 및 근무 / 교육 / 활동 / 기타 네 가지로 묶었다. 기존 세부 분류 식별자와 저장 자료는 보존하며, 대분류별 모아 보기와 세부 분류 검색을 제공한다.
- 경력 선택 시 회사·기관명 한 번, 직무·직책, 재직기간, 담당 업무를 입력하는 전용 양식으로 전환한다. 부서·근무 형태·공식 주소·대표 전화·홈페이지·증빙자료는 선택이다.
- 새로 가져오는 주소·지도는 기본 비공개이며 다모아와 각 프로필에서 표시 여부를 선택한다. 이미 게시한 프로필은 원본 편집만으로 변경하지 않는다.
- 프로필 관리 메뉴는 이동 없이 하위 메뉴를 펼친다.
- 주소 공개 프로필의 지도는 본문 마지막에 왼쪽 정렬한 최대 320px 정사각형으로 표시한다. 기관명과 주소는 지도 아래에 둔다. 근무 기관 제목·본인 입력 안내문·외부 지도 이동 버튼은 제거했다.
- 지도 장애 시 응답이 없어도 예외가 나지 않도록 처리한다. 공개 조회와 편집 미리보기의 외부 요청 시점을 구분하고 개인정보처리방침을 실제 동작에 맞췄다. 지도 제공자의 표시·저작권은 유지한다.
- 네이버 등록 업체 검색/플레이스 선택은 이번 배포에 포함하지 않는다. 공식 검색 API의 저장·재사용 조건을 확인한 뒤 별도로 설계한다.
- 신규 DB 변경·자료 삭제·자동 공개·인증/키 변경은 이번 앱 배포에 포함하지 않는다. 배포 상태와 최신 검증 결과는 별도 배포 보고서에 기록한다.
