# 다모아 개인 저장 한도 50MB

2026-11-19 사용자 요청. 후속 운영 배포 요청으로 서버 제한 변경을 적용했다. 기존 파일 15개·4,759,224바이트와 기록17건의 내용 지문 및 함수 실행 권한이 적용 전후 동일함을 확인했다. 웹 변경은 작업 브랜치/PR 검증 후 병합·배포한다.

- `STORAGE_LIMIT`를 50×1024×1024(52,428,800바이트)로 변경했다. 화면의 한도·사용률·업로드 오류와 기존 브라우저 저장 문구는 같은 상수에서 표시한다.
- 기존 자료/기록을 자동 정리하거나 삭제하지 않는다. 한도 초과 계정도 기존 자료 읽기·기존 파일을 사용하는 기록 수정을 유지한다. 새 첨부만 현재 총량과 합산해 검사한다.
- 파일당 10MB와 기존 허용 형식, 비공개 버킷·소유자 검사·계정별 업로드 잠금은 유지한다. 프로필 상세 미디어 전용 200MiB는 별도이며 이번에 바꾸지 않는다.
- 서버의 새 파일 사전 예약 한도만 50MiB로 줄이는 `supabase/migrations/20261119012655_damoa_storage_limit_50mb.sql`과 `supabase/rollback/damoa_storage_limit_50mb.sql`을 준비했다. 기존 파일 예약 재사용은 총량 검사 전에 허용되며 권한·원본·행을 수정하지 않는다.
- 기존 업로드 방식은 실제 파일 크기를 확정하기 전 10MiB를 사전 예약하므로 새 업로드 시 10MiB 여유가 필요하다. 이번 변경은 이 검증·동시 업로드 보장을 유지한다.
- 관련 5개 테스트 모음 40개, 타입 검사 통과. 화면의 50MB/초과 사용량 표시, 40MB+10MB 허용, 41MB+10MB 및 60MB+추가 첨부 차단을 확인했다.
- 독립된 메모리 PostgreSQL에서 실제 함수 실행 11검사 통과: 50MiB 예약 경계·초과 차단, 미확정 예약 합산, 기존 파일 재사용·원본 보존, 계정별 분리, 미인증 차단, 재적용·복구·기존 함수 권한 유지. 운영 자료 쓰기 없이 수행했다.

- 릴리스 전 검색 접기/펼치기·표시 정보 검색·다모아 한도와 기록 호환 관련 7개 모음55검사·타입 검사 통과. 검색칸은 기본 숨김이며 영상 옆 돋보기로 펼친다. Esc 또는 돋보기를 다시 누르면 검색어를 지우고 원래 화면으로 복귀한다.
- 운영 함수 정의의 50MiB 한도와 기존 소유자 검사·계정별 잠금·파일 재사용 순서를 확인했다. 검증을 위해 운영 자료를 추가하거나 수정·삭제하지 않았다. 서버 보안 권고 조회도 수행했으며 기존 전체 보안 후속 과제 완료를 의미하지 않는다.
