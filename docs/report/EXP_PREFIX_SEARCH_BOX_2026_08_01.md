## 1절. 경력 (전)/(현) 자동 표기

`is_current` 기준으로 기관명 앞에 접두어를 붙였다.

- **공개 프로필** (`app/experts/[id]/page.tsx`): `(현) `/`(전) ` + 기관명.
- **마이페이지에도 적용** (판단 지점): `ExperienceSection.tsx`의 "추가된 경력"
  보기 모드에도 동일 접두어를 붙였다 — 본인 관리 화면이라 필수는 아니지만,
  공개 화면과 표기가 다르면 "내 화면에는 없는 (전)이 공개 화면에 붙는" 식의
  예측 불가능함이 생기므로 일관성을 택했다.
- **기간 비공개와의 상호작용** (판단 지점): 지시서 권장대로 `period_visible=false`
  항목에서도 접두어는 항상 표시한다. `(전)/(현)`은 날짜가 아니라 `is_current`
  불리언 기준이고, "언제부터 언제까지"와 "지금 다니는 곳인지"는 별개의 정보라는
  PR #54/#57의 `is_current` 노출 유지 근거를 그대로 따랐다. 날짜 블록은 기존처럼
  `start_date`가 NULL이면 렌더링되지 않으므로 기간은 계속 가려진다.

검증: 프로덕션 김준석 프로필(현재 근무 1건 + 과거 2건)에서 "(현) 삼성마디탑의원",
"(전) 서울통정형외과 모란점"/"(전) 바로튼튼365의원"으로 정확히 표기됨을 배포 후
실사이트에서 확인.

## 3절. 검색창 + 상세검색

### DB — `search_public_experts()`에 `p_query` 추가
`display_name`/`headline` 대상 ILIKE 부분일치(대소문자 무시), 빈/공백 검색어는
전체 목록. 현재 데이터 규모에서는 전체 스캔으로 충분하며, 수천 건 규모가 되면
`pg_trgm` GIN 인덱스를 고려하라는 주석을 함수 안에 남겼다.

**지시서와 다르게 구현한 부분**: 지시서의 `CREATE OR REPLACE` 대신 **DROP 후
재생성**했다. Postgres에서 CREATE OR REPLACE는 파라미터 목록이 다르면 기존
함수를 대체하지 않고 **오버로드를 새로 만든다** — 구 5-파라미터 함수가 남으면
`p_query` 없이 호출할 때 두 후보(5개 vs 6개+기본값) 사이에서 PostgREST가
결정하지 못하는 모호성 에러가 생긴다. 적용 후 `pg_proc` 조회로 6-파라미터
단일 함수만 존재함을 확인했다.

호환성: 구 프론트(배포 전 코드)의 named-args 호출은 `p_query`가 DEFAULT NULL로
채워져 그대로 동작 — PR #57과 달리 DB 선적용~프론트 배포 사이 다운타임 창이
없다.

### UI — `ExpertFilters.tsx`
- 검색창(`<input type="search">`, placeholder "이름, 소개로 검색") + 우측
  "상세검색" 버튼. 클릭 시 기존 3개 select(직군/지역/분야)를 펼치고 접는 토글.
- **디바운스 선택** (판단 지점): 지시서 권장대로 350ms 디바운스를 택했다 —
  검색 버튼 없이 타이핑을 멈추면 자연스럽게 반영되고, Enter 방식보다 발견성이
  좋다.
- 디바운스와 기존 경쟁 상태 방지 로직(`paramsString` 함수형 setState, PR #56)의
  결합: 입력창 값(`queryInput`)과 마지막으로 URL에 반영한 값(`lastPushedQueryRef`)
  을 분리해, 커밋된 URL의 query가 우리가 반영한 값과 다를 때(=뒤로/앞으로 가기
  등 외부 변경)만 입력창을 동기화한다 — 디바운스 대기 중인 타이핑을 라우팅
  커밋이 덮어쓰는 상황을 막는다.
- **상세검색 기본 펼침 조건** (판단 지점): 페이지 진입 시 URL에
  `profession`/`region`/`specialty` 중 하나라도 있으면 펼친 상태로 시작 —
  지시서 권장 그대로(선택된 필터가 접혀서 안 보이면 혼란). 검색어(query)만
  있는 경우는 검색창에 이미 보이므로 펼치지 않는다. 펼침 상태는 버튼 색상
  (파랑 강조)으로도 표시.
- 토글을 닫아도 선택된 필터 값은 URL/상태에 그대로 남는다(접힘은 표시만).

### 연결부
- `app/experts/page.tsx`: `SearchParams`에 `query` 추가, RPC에 `p_query` 전달,
  `LoadMoreExperts`의 `key`에도 포함(검색어 변경 시 목록 리셋).
- `app/experts/LoadMoreExperts.tsx`: `Filters.query` + `loadMore()`의 RPC에
  `p_query` 전달 — 지시서가 강조한 "더보기 시 검색어 유실" 버그 방지.

  건드리지 않아 새 ERROR가 생길 변경면이 없다.

  펼침/접힘 시 필터 값 유지, `?profession=...` 진입 시 기본 펼침, (전)/(현)
  표기, 홈/목록의 "지역별" 제거 확인. (아래 배포 절 참고)

## 지시서에 없어서 스스로 판단한 부분

1. **DROP+CREATE로 시그니처 변경** (위 3절 — CREATE OR REPLACE의 오버로드
   함정 회피).
2. **마이페이지 경력 목록에도 (전)/(현) 적용** (위 1절 — 공개 화면과 일관성).
3. **검색어만 있는 경우 상세검색 기본 접힘** (위 3절 — 검색창에 이미 보이는
   정보라 펼칠 이유 없음).
4. **디바운스 반영 시 trim 처리**: 공백만 입력한 검색어는 URL에 반영하지 않고
   key를 제거해 `/experts`가 깔끔하게 유지되도록 했다(RPC의 공백 무시 로직과
   이중 방어).
