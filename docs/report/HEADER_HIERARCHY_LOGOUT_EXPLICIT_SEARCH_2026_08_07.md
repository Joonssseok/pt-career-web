# 헤더 위계/로그아웃 + 검색 명시적 제출

## 1. 헤더 "전문가 찾기" 위계 조정

왼쪽 그룹의 정렬을 `items-center` → **`items-baseline`** 으로 변경 + 미세
오프셋(`translate-y-px`). 로고(text-lg/xl bold)와 "전문가 찾기"(text-sm)가
베이스라인 정렬되면서 링크가 자연스럽게 한 단계 낮은 위치·작은 크기의 하위
항목으로 읽힌다 — 헤더 높이(h-16) 변경 없음, 로그인/비로그인 공통(선택지 중
"가벼운 오프셋" 방식 채택: lockup 세로 스택은 h-16 안에서 클릭 영역이
좁아지고 내비게이션 링크가 브랜드에 종속돼 보이는 정도가 과함).

## 2. 로그아웃 버튼

- 기존 로그아웃 구현을 먼저 검색 — `/my` 페이지(`app/my/page.tsx`)에 **서버
  액션 + `<form>`** 패턴(`'use server'` 인라인 액션 → `supabase.auth.signOut()`
  → `redirect('/login')`)이 이미 있어 그대로 재사용(중복 구현 없음, 클라이언트
  컴포넌트 분리 불필요 — SiteHeader가 서버 컴포넌트인 채 유지).
- 위치: 로그인 상태의 "마이페이지" 오른쪽, 회색 텍스트 버튼.
- 리다이렉트는 기존 패턴 그대로 `/login`. 서버 액션의 redirect는 풀
  네비게이션이라 헤더가 즉시 로그아웃 상태로 재렌더 — "로그인 상태 미반영"
  계열 버그 없음(실화면으로 확인, 아래).

## 3. 검색 명시적 제출

- 350ms 디바운스 자동 커밋 `useEffect` **제거** → `commitQuery()` 함수로
  분리해 **돋보기(🔍) 버튼 클릭과 입력창 Enter**(권장안 채택)에서만 호출.
- `lastPushedQueryRef` 기반 외부 변경(뒤로/앞으로 가기) 입력창 동기화 로직은
  그대로 유지.
- 버튼 배치: `[검색 입력창] [🔍] [상세검색]` — 지시서 지정 순서.
- 직군/지역/분야 select 3개는 범위 밖이라 기존 즉시 반영 유지.
- `LoadMoreExperts` 확인: 서버 페이지가 URL `query`를 `filters`로 내려주고
  더보기 RPC가 그대로 사용 — **추가 변경 불필요 확인**(커밋된 URL 기준이라
  명시적 제출 전의 미커밋 입력은 애초에 전달되지 않음).

## 검증

- `pnpm tsc --noEmit` / `pnpm build`(14 라우트) / `pnpm test`(7 suites /
  63 tests) 통과.
- 실화면(로컬, 실제 로그인 세션 — 검증 후 계정 삭제):
  | 항목 | 결과 |
  |---|---|
  | 헤더 왼쪽 그룹 | `items-baseline` + `translate-y-px` 적용 렌더 확인 ✓ |
  | 로그인 헤더 | "HdrTest님 환영합니다 · 마이페이지 · 로그아웃(form)" ✓ |
  | 로그아웃 클릭 | `/login` 리다이렉트 + 헤더 즉시 비로그인 상태("로그인·회원가입") ✓ |
  | 검색 타이핑 중 | 1.5초 대기에도 서버에 검색 요청 없음(디바운스 제거) ✓ |
- **환경 제약 1건**: 돋보기 클릭 → URL 반영의 브라우저 검증은 이 세션의
  브라우저 패널이 백그라운드(`visibilityState: hidden`)라 Next.js
  `router.push`의 커밋이 보류되는 기존 문서화된 아티팩트(PR #56/#58 검증 때와
  동일) 때문에 이 환경에서는 결정적으로 확인할 수 없었다. 다만 `commitQuery`
  → `updateFilter` → `paramsString` → `router.push` 체인은 **직군/지역/분야
  select가 쓰는 것과 완전히 동일한 코드 경로**이고, 그 경로는 프로덕션
  visible 탭에서 수차례 실증됐다(디바운스 시절의 검색 커밋도 동일 경로로
  동작했음). 병합 후 실브라우저에서 돋보기 클릭 1회 확인을 권장.
