# 상세소개 사진 크기·자르기 · 2026-11-18

상태: 로컬 실제 작성창 저장 연결 및 독립 미리보기 완료. 앱 배포·커밋·푸시·병합·현황판 게시는 수행하지 않음.

## 적용 범위

- 상세소개 사진 블록에 Tiptap 3.34.0 공식 ResizableNodeView의 모서리 드래그와 10~100% 너비 조절을 적용했다. 키보드 방향키와 모바일 슬라이더도 지원한다.
- 자르기는 후속 사용자 요청으로 MIT Cropper.js 2.3.1로 교체했다. 이전 react-easy-crop 의존성을 제거했다. 기본 선택 영역·8방향 손잡이·이동·크기 변경·자유/원본/1:1/4:3/16:9/3:4 비율·영역 크기 버튼·적용/취소를 제공한다.
- 원본 복원은 너비·자르기 설정만 제거한다. 원본을 재인코딩하거나 덮어쓰지 않고 GIF도 같은 원본 URL로 표시한다. 새 파일이나 추가 저장 공간을 만들지 않는다.
- 문서 이미지 속성에 widthPercent와 crop의 x/y/width/height 백분율만 저장한다. 화면 폭이 바뀌어도 같은 비율과 영역으로 표시한다. 편집·실제 표시·공개 전 확인은 같은 렌더러를 사용한다.
- 자동 저장 중 적용이 거절되면 자르기 창과 선택 영역을 유지하고 재시도를 안내한다. 취소는 문서를 변경하지 않는다.
- 독립 미리보기는 기존 본인 사진을 읽어 브라우저에서만 조절하며 저장·업로드하지 않는다. 실제 작성창 3단계의 초안 저장은 서버에 연결되어 있다.

## 저장·보안

- 20261118130222_image_presentation 적용. 기존 순수 문서 검증 함수의 이미지 표시 속성 허용 목록만 확장했다. 새 테이블·권한·Storage 설정·공개 범위 변경은 없다.
- 너비는 정수 10~100, 영역은 유한한 수와 원본 범위 내 좌표만 허용한다. 임의 속성·외부 src·HTML/CSS·동영상의 이미지 표시 속성은 거절한다.
- 파일 UUID·MIME·본인 소유·업로드 완료 검사, 비공개 파일의 기존 공개/소유자 판정, 별도 게시 절차는 유지한다.
- 연결 DB에서 기존 본인 사진 문서의 크기와 영역을 저장→재조회한 후 트랜잭션 전체를 롤백했다. 공개 스냅샷과 원본 업로드 정보 불변 확인. 기존 버전/첨부/업로드 행 전체 지문도 검증 전후 동일했다.

## 확인

- TypeScript 통과. 전체 자동 검사 80묶음/648항목 통과 후, 추가 자르기 수명주기·저장 거절 재시도 4항목, 실제 Tiptap 이미지 노드 초기 생성/저장 중 편집 가능 상태 전환 1항목 및 영향받은 자동 저장 검사 통과(기존 로컬 DB 통합 묶음 6개 제외).
- 별도 PGlite의 실제 SQL 저장·공개 함수 42검사 통과. 표시 속성 저장/재조회, 공개 결과의 속성 보존, 잘못된 값 차단, 원본 메타데이터 보존 포함.
- 실제 브라우저의 쓰기 없는 미리보기에서 기존 본인 사진으로 모서리 드래그 70%, 슬라이더, 1:1 자르기/이동/확대, 재열기, 취소, 원본 복원을 확인했다. 편집/결과의 원본 URL·자르기 스타일 동일.
- 최종 관련 4묶음/80항목 재확인 통과. 390×844 화면에서 자르기 창 적용/재열기와 너비 변경, 가로 넘침 없음 확인. 실제 모바일 기기의 터치/펜 손잡이 드래그는 미검증이다. 설치된 Tiptap의 touch-end 누락은 로컬 포인터 캡처로 보완하고 마우스는 공식 동작을 사용한다.

## 복구와 한계

- 앱은 아직 운영 배포하지 않았다. 로컬 실제 작성창에서 저장한 초안은 연결 DB에 남지만 별도 게시 전에는 공개되지 않는다.
- 이전 앱 화면으로 되돌리더라도 새 문서 속성·원본 파일을 삭제하지 않는다. 새 속성이 저장된 뒤 DB 검증 함수를 무조건 예전 허용 목록으로 좁히면 기존 초안 저장이 거절될 수 있으므로 호환 확장은 유지한다.
- 자르기는 보이는 영역을 정하는 기능이다. 원본을 제공받을 권한이 있는 사람에게 이미지의 가려진 부분을 영구적으로 제거하는 용도로 쓰지 않는다.
- 원본 업로드/운영 게시를 수반하는 시험은 수행하지 않았다. 기존 보안 후속 항목은 이번 기능으로 완료 처리하지 않는다.


## Cropper.js 교체 후속 · 2026-11-18

- 기존 원본 및 백분율 표시 속성을 그대로 사용한다. 서버/DB/권한/저장 형식 변경과 추가 배포는 없다. Cropper.js는 자르기 창을 열 때만 불러온다.
- 공식 CropperCanvas/Image/Selection/Grid/Handle 요소와 API를 사용한다. 원본은 고정하고 선택 영역을 움직인다. 표시 영역은 원본 범위 내 1~100%만 허용하며 HTML/외부 이미지/회전/반전/파일 재생성은 추가하지 않았다.
- 선택한 영역을 원본 백분율로 변환해 기존 저장 경로에 전달하고, 기존 문서를 다시 열면 Cropper.js 선택 영역으로 복원한다. 창 크기가 바뀔 때 같은 영역을 비율로 복원한다. 취소/저장 중 재시도/원본 복원 동작을 유지한다.
- 글 편집 미리보기에서는 편집기 스타일을 처음부터 포함해 첫 진입 시 도구 모양이 누락되는 문제를 함께 해결했다. 실제 편집기의 지연 로딩은 유지한다.
- 브라우저에서 기존 본인 사진으로 모서리 드래그, 선택 영역 이동, 적용·재열기, PC/390×844 화면 전환과 영역 크기 버튼을 확인했다. 편집/출력의 원본 URL과 표시 영역 동일. 실제 기기의 터치/펜 입력은 미검증이다.
- TypeScript, 교체 관련 6묶음/92검사 및 전체 84묶음/665검사 통과(기존 로컬 DB 통합 묶음 6개 제외). 좌표 변환·범위 밖 거절·기존 영역 복원·화면 크기 변경·실패한 이미지 로딩·취소·저장 중 재시도를 포함한다.
- 독립 미리보기만 조작했으며 사진 업로드/실제 초안 변경/공개 게시는 하지 않았다. 커밋·푸시·병합·배포·온라인 현황판 게시 없음.
