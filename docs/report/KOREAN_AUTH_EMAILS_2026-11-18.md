# 한글 인증 메일과 발신 도메인 연결

- 사용자 지정 발신자: PT Career, noreply@ptcareer.co.kr.
- 가입 확인, 비밀번호/PIN 재설정, 이메일 변경 확인의 한글 양식 3개를 준비했다. 현재 PIN과 비밀번호 재설정은 같은 recovery 메일 유형을 사용한다. 제목은 공통 한글 안내이며 본문·버튼은 기존 RedirectTo가 PIN 재설정 경로인지에 따라 나뉜다.
- ConfirmationURL은 변경하지 않고 그대로 사용해 기존 인증·세션·이동 흐름을 유지한다. 이메일 변경의 양쪽 주소 확인, 가입 확인 여부, 기존 보안 알림 활성화 상태는 변경하지 않는다. 회원에게 테스트 메일을 무작위로 발송하지 않는다.
- 로컬 설정은 같은 양식을 참조한다. 이 파일 변경만으로 운영 Supabase 설정이 바뀌지 않는다. 운영 적용은 SMTP 설정과 대시보드 양식을 별도로 저장해야 한다.
- 발송 서비스: Resend. 도메인: ptcareer.co.kr. 지역: Tokyo. 클릭/열람 추적은 끈 상태로 유지한다. 수신 기능과 기존 홈페이지 DNS는 변경하지 않는다. 인증에 필요한 DNS 항목은 서비스가 실제 제시한 값으로만 추가한다.
- SMTP 비밀값은 소스·로그·채팅·보고서에 보관하지 않는다. 연결 대상과 필요 권한을 준비한 후 보호된 입력은 사용자가 직접 진행한다.
- 운영 SMTP 연결·도메인 인증·한글 양식 적용 및 사용자 본인 메일 수신 확인을 완료했다. 실제 발송 시험 범위는 아래에 구분한다.

## 도메인 인증 진행 결과

- 사용자가 가비아의 인증용 DNS 4개 저장을 승인했다. 기존 홈페이지 A/CNAME 2개를 보존하고 Resend가 제시한 서명 TXT, 발송 CNAME 2개, DMARC 모니터링 TXT를 추가했다. 메일 수신 기능은 활성화하지 않았다.
- 가비아 저장 완료·6개 레코드 유지, 권한 DNS에서 인증 항목 4개 게시, Resend의 도메인 Verified/Ready를 확인했다.
- 발송 키는 Sending access 및 ptcareer.co.kr로 범위를 한정한 생성 직전 화면을 준비했다. 키 생성·복사·Supabase 비밀번호 입력과 저장은 사용자 직접 진행을 요청했다. 키 원문을 조회·보관하지 않는다.
- 위 항목은 연결 준비 단계의 기록이며, 최종 적용 결과는 아래와 같다.

## 운영 적용 및 발송 확인

- 운영 Supabase에 가입 확인, 비밀번호/PIN 재설정, 이메일 변경의 한글 제목과 본문을 저장했다. PIN/비밀번호는 기존 재설정 경로에 따라 본문을 구분한다.
- 사용자 지정 SMTP는 Resend, 발신자는 PT Career <noreply@ptcareer.co.kr>로 연결했다. 사용자가 발송 전용·해당 도메인 한정 교체 키를 직접 입력하고 저장했다.
- 최초 시험은 SMTP 인증 오류(535)로 발송되지 않았다. 키 교체 후 2026-11-18 15:45 KST에 사용자가 지정한 본인 주소로 재설정 안내 1통을 발송했다.
- 사이트 발송 성공 표시와 Resend의 Delivered 상태를 확인했다. 실제 발신자, 한글 제목, 한글 비밀번호 재설정 본문·버튼 표시를 확인했다. 인증 링크를 실행하거나 비밀번호/PIN을 변경하지 않았다.
- Delivered는 수신 메일 서버 전달 확인이며, 이후 사용자가 실제 메일 수신도 확인했다. 가입·PIN·이메일 변경 각각의 실제 발송 시험은 수행하지 않았다.
- 기존 발송 키는 삭제하지 않았다. 사용하지 않는 키 정리는 별도 확인 후 진행한다. 보고서에는 수신자 주소, 비밀키, 인증 링크를 기록하지 않는다.
