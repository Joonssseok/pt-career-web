# 증빙 개인정보 가리기 — 로컬 구현·검증

기준: 사용자가 전달한 `MASKING_HANDOFF_2026-11-20.md`의 6장 가. 인계서는 원본 프로젝트 `docs/report/profile-template-handoff/`에서 읽었다. 현재 실제 다모아 한도는 50MiB이며 인계서의 100MB는 이전 값이다.

## 구현한 범위

- 실제 공개 전 확인의 증빙 선택 → 전체 화면 가리기 → 사본 확인·체크 → 첨부 목록 반영 흐름을 연결했다. 별도 개발 미리보기: `/preview/evidence-masking`.
- 원본은 수정하지 않는다. canvas의 새 픽셀 그림에 불투명 검정을 칠하고 JPEG로 재인코딩한다. 새 사본 ID와 중립 파일명을 사용하며, 심사 업로드 함수가 원본 ID를 그대로 반환하던 지름길을 새 제출에서는 차단했다.
- 기존 심사와 동일한 참조는 그대로 보존한다. 새 제출·변경된 제출만 가리기 확인을 요구한다. 면허 자료도 같은 선택/사본 흐름을 거친다.
- 끌어서 가리기, 인식한 줄/글자 선택, 모두 가리기, 지우기·되돌리기, 100~300% 확대와 화면 이동을 제공한다. 작은 화면의 안내는 기본 접힘이며 펼칠 수 있다.
- 새 파일 입력과 기존 자료 선택에서 PDF를 차단한다. 다모아 자체 PDF 보관·본인 원본 열기는 유지한다.
- 가릴 곳이 없어도 직접 확인 체크를 요구한다. 개인정보 잔여 및 필요한 글자 가림 경고는 차단하지 않는다. 늦게 인식 결과가 도착하면 확인 체크를 다시 요구한다.
- 공개 선택은 사본 ID에만 매핑한다. 첨부 반영만으로 저장·심사·공개되지 않으며 실제 게시 절차는 유지한다.
- 관리자에 ‘개인정보 가림 부족’ 사유 입력 버튼을 추가했다. 누르는 것만으로 반려하거나 삭제하지 않는다.

## 기기 내 글자 인식

- Tesseract.js 6.0.1, tesseract.js-core 6.1.2, kor/eng 학습 자료 1.0.0을 고정했다. 설치 전 이름·용량·출처를 보고했다. 기존 잠금 파일 항목은 그대로이며 필요한 의존성만 추가했다.
- 공식 배포 파일을 빌드/개발 시작 때 사이트 정적 폴더로 복사한다. worker/engine/language 경로는 전부 같은 사이트다. 첫 인식의 선택 엔진+두 언어+worker 자산은 약 8.59MB(압축 전 전달 파일 합계)다. 기기별 SIMD 선택과 캐시/전송 압축에 따라 실제 전송량은 달라진다.
- 화면 진입 때만 인식기를 불러오며 20초 제한·취소를 둔다. 실패해도 수동 가리기와 확인은 계속 가능하다. 원본이나 인식 결과를 외부 OCR 서비스로 전송하거나 서버/분석 로그에 저장하는 코드를 추가하지 않았다. 가림 좌표도 사본 생성 뒤 서버로 보내지 않는다.
- 가상 한글 문서 1200×1500 및 기울임/흐림/축소한 가상 문서에서 이름·식별번호·주소·전화·이메일 5개 항목을 모두 인식했다. 본체 준비 포함 약 1.7초, 각 인식은 0.74/0.69초. 신뢰도 표시는 89/87이었으며 정확도 비율을 뜻하지 않는다. 실제 휴대폰 촬영 자료와 손가락 조작은 미검증이다.

## 확인 결과

- 관련 9묶음 113개 검사 통과. 타입 검사 통과. 검사에는 원본 ID/확인 안 된 blob 제출 차단, 사본 생성/체크, PDF 차단, OCR 실패 후 수동 확인, 경고가 있어도 확인 후 진행, 기존 워터마크·자동 저장 회귀가 포함된다.
- 브라우저의 가상 자료에서 끌기+모두 가리기로 사본을 만들고 실제 다운로드했다. JPEG 1200×1500 / 109,913바이트 / EXIF 0개였고, 사진·식별번호 뒷자리·주소·전화·이메일의 샘플 픽셀이 모두 검정임을 파일에서 확인했다.
- 375px 폭에서 가로 넘침 없음, 150% 확대, 화면 이동의 실제 스크롤 변화 확인. 실제 모바일 기기 시험을 대신하지 않는다.
- 프로필 작성 예시 화면에서도 자료 선택 → 가리기 → 확인 → 첨부 반영을 직접 진행했다. 원본 체크가 해제되고 새 JPEG 사본만 체크되며 비공개 기본값을 유지하는 것을 확인했다. 실제 게시·업로드는 누르지 않았다.
- 기존 운영 자료는 건수만 읽었다. 조회 시점 승인·공개 증빙 심사 0건 / 공개 파일 참조 0건. 원본 열람·삭제·공개 변경 및 검증용 실제 제출은 하지 않았다.
- 실제 촬영된 면허증, 10MB에 가까운 대형 사진의 휴대폰 성능, 네트워크 로그 전수 감사는 미검증이다. 긴 변 1800px로 인식 입력을 줄이고 수동 처리는 원래 픽셀로 유지한다. 읽을 사진은 3200만 화소까지 제한한다.

## 별도 승인 전 진행하지 않은 범위

1. 서버에서 새 심사를 사진·가린 사본 표시가 있는 파일로만 제한하기. 현재는 클라이언트 검사이므로 직접 API 호출 우회 방지는 완료되지 않았다. `maskedCopy`는 로컬 UI 표시이며 서버가 신뢰할 보안 증명이 아니다.
2. 사본을 원본과 서버에서 확실히 구분하는 표시, 반려 시 사본 참조 해제·저장소 정리. 기존 원본을 파일명이나 생성 날짜로 추정하여 삭제하면 안 된다. 반려 사유와 타 심사에서 사용하는 사본도 보존해야 한다.
3. 옛 공개 자료가 생기거나 발견되면 건별 관리자 검토. 일괄 비공개·기존 인증 해제 없음.
4. 약관/개인정보 처리방침의 ‘사본만 전달/반려 사본 삭제’ 문구는 해당 서버 동작 적용 후 검토할 후속 작업이다. 아직 그런 삭제를 보장하지 않는다.

현황판 게시용 요약: ‘증빙 자료 개인정보 가리기 — 로컬 화면·사본 생성·기기 내 인식 구현 및 113검사 통과. 서버 사본 표시/제출 차단/반려 시 사본 삭제는 별도 승인 후 진행. 기존 보안 후속 작업 유지.’

최초 구현 시 운영 DB 변경·앱 배포는 수행하지 않았다. 현황판만 버전72(D-73)로 게시했고 기존 공유 대상과 앱 운영 버전(PR167)은 유지했다.

## 후속 배포 요청 · 2026-11-20

사용자가 미리보기 확인 후 배포를 요청했다. 이번 릴리스는 위 1차 화면·사본 생성 범위에 한정한다. 운영 DB·권한 변경과 반려 사본 자동 삭제는 포함하지 않는다. 직접 API 호출에 대한 서버의 사본 강제 검증은 후속 작업이며, 이 릴리스가 그 검증까지 완료한 것으로 표시하지 않는다. 화면에도 반려 사본 자동 삭제를 보장하지 않는 안내를 유지한다. 원본·기존 심사 보존과 공개 승인 절차는 유지한다.
