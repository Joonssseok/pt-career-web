# 마이페이지 밀도·계정 메뉴·전 페이지 광고

사용자 승인 릴리스 범위 · 2026-11-08

- 마이페이지를 상단 기록 요약, 중앙 프로필/최근 활동/공유 관리, 우측 공개·심사·계정 관리로 재배치했다. 글꼴과 공통 프레임을 유지하고 명함 도구는 펼쳐서 사용한다.
- 요약은 로그인한 본인의 프로필·활동·파일·심사만 조회한다. 전체 건수와 최근 목록을 구분하고 조회 실패를 0건으로 표시하지 않는다. 미게시·비공개 프로필의 공유 제한과 정지·탈퇴 요청 배너를 유지한다.
- 마이페이지의 이력서 다운로드 링크를 제거하고 공개 설정은 ‘프로필 전체 공개’와 토글만 표시한다. 기존 이력서 API와 다른 화면의 기능은 삭제하지 않는다.
- ‘공유 설정’을 ‘공유 관리’로 통일한다. ‘내정보 수정’과 ‘계정 설정’ 대분류를 ‘계정 관리’로 합치고 내정보 수정 / 로그인 정보·연락처 / 약관내역 / 회원탈퇴를 제공한다. 데스크톱·모바일에 같은 메뉴를 사용한다.
- PIN 확인은 기존 `/my/personal` 서버 보호에만 적용한다. 약관내역·회원탈퇴·메뉴 펼침에 PIN 확인을 추가하지 않는다. 로그인 후 PIN 설정·복구와 회원탈퇴 확인 절차는 유지한다.
- 좌우 160×600 광고를 전체 경로 대상으로 한다. 1680×960 이상 화면, 본문 바깥 배치·푸터 회피·홈 검색창 간격, 빈 자리 흰색, 이미지 referrer 미전송, 비공개 경로·개발/관리자 통계 제외를 유지한다.
- 예시 화면 `/preview/my-page`는 개발 환경에서만 제공한다. 예시 공유·메시지·명함 저장은 실제 실행하지 않는다.

## 검증

- TypeScript 검사 통과.
- DB에 쓰지 않는 자동 검사 53개 묶음 / 338개 항목 통과.
- 전체 검사 시 별도 테스트 DB 키가 필요한 기존 통합 검사 6개 묶음 / 62개 항목은 설정 부재로 실행되지 않았다. 운영 키를 주입하거나 운영 자료를 생성·삭제하지 않았다.
- 실제 로그인 계정의 로컬 마이페이지 조회, 계정 관리 하위 메뉴, 약관내역·회원탈퇴의 PIN 없는 진입, 내정보 수정의 6자리 PIN 확인 화면을 읽기만 하여 확인했다. 실제 PIN 입력·정보 수정·탈퇴·공개 전환·심사 제출은 수행하지 않았다.
- 로컬 PC/모바일 마이페이지 배치, 명함 접기/펼치기, 광고 두 자리의 본문/푸터 비겹침을 확인했다. 실제 활성 광고는 없었으며 새 광고 계약·게재·과금은 생성하지 않았다.
- 운영 배포와 운영 화면 검증 결과는 PR·Vercel 배포·개발 현황판 기록에서 별도로 확인한다. DB·Storage·인증 권한 변경은 없다.
