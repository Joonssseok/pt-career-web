# 프로필 자료 자동 연결·일괄 심사 릴리스

2026-11-08. 사용자가 실제 서버 연결과 검증, 커밋·푸시·병합·배포를 승인했다. 현황판에는 기능·검증 결과·배포 근거만 기록하고 비밀값·회원 서류·실제 심사 내용은 포함하지 않는다.

## 결과 동작

- 프로필로 가져온 다모아 활동의 증빙자료를 자동 연결한다. 기존 자료를 중복 업로드하지 않으며, 저장된 선택과 사용자의 제외를 존중한다.
- 공개 전 확인의 항목마다 회색 클립과 연결 파일 개수를 표시한다. 자료가 없으면 생략하고, 누르면 해당 연결 자료를 먼저 미리 본다. 이 편집 도구는 실제 공개 프로필에 표시하지 않는다.
- 주 동작은 `프로필 게시`로 정리한다. 제출 건수·관리자 확인 범위·서류 공개 조건을 안내하는 팝업에서 동의 체크 후 `동의하고 게시`를 눌러야 처리한다. 취소 후 재진입 시 체크를 초기화하고 처리 중 중복 실행을 막는다.
- 변경 없는 승인·심사 중·반려 내역은 재요청하지 않는다. 새 자료나 수정한 항목만 심사 대상으로 계산한다. 소개·근무 기관처럼 고정 식별자를 쓰는 항목도 내용 변경을 비교한다.
- 제외한 항목·공개할 내용이 없는 항목·증빙 없는 항목은 새로 심사 요청하지 않는다. 자료 조회 실패 중에는 게시를 막는다.
- 서류는 기본 비공개다. 파일 공개 선택·관리자 승인·현재 공개 프로필 포함 조건과 워터마크 사본 제공 규칙을 유지한다. 기존 자료의 자동 공개·삭제나 새로운 서류 진위 인증은 추가하지 않는다.

## 서버 처리와 호환성

- 운영 함수 `publish_profile_with_reviews(uuid,jsonb,jsonb)`를 추가했다. 기존 개별 저장·기존 게시 함수와 테이블은 유지하므로 이전 웹 코드도 작동한다.
- 함수는 실제 로그인한 본인 소유의 저장된 버전, 저장 내용 일치, 항목 포함 여부, 자료 소유·업로드 완료 여부, 기존 심사 갱신 시점을 확인한다. 익명 실행은 허용하지 않는다.
- 한 트랜잭션에서 필요한 심사를 저장한 뒤 기존 대표 게시 함수를 호출한다. 심사 저장 또는 최종 게시가 실패하면 둘 다 취소된다. 기존 게시 함수와 프로필→버전 잠금 순서를 맞춰 배포 전후 혼용에 대비했다.
- 새로 추가한 파일의 실제 업로드는 DB 트랜잭션보다 먼저 수행된다. 게시 실패 시 미연결 업로드 정리는 기존 기능을 따른다. 자료 선택의 임시 변경은 최종 게시 전 새로고침하면 초기화되며 별도 서버 초안으로 저장하지 않는다.
- 적용 파일은 `supabase/migrations/20261108082152_profile_publish_with_reviews.sql`이다. 웹 코드 배포 결과는 해당 PR 및 Vercel 운영 배포 내역에서 확인한다.

## 검증 근거

- 실제 운영 DB에서 `tests/profile-publish-reviews-permissions.sql`을 실행했고 전체 롤백했다. 검증용 프로필 잔존 0건을 별도 확인했다.
- 익명/타인 요청 차단, 저장 내용 불일치·중복 항목·존재하지 않는 파일·오래된 심사 시점·제외 항목 차단을 확인했다.
- 단일 호출의 2개 항목 접수·대표 프로필 하나 유지·기본 파일 비공개·미승인 배지/자료 미노출·변경 없는 심사 보존·수정 내용 재심사를 확인했다.
- 뒤 항목의 실패와 최종 게시 실패 각각에서 앞 항목의 변경도 취소되는 것을 확인했다. 자료 없는 게시도 확인했다. 실제 회원 자료 게시나 관리자 승인을 영구 기록하는 방식으로 검증하지 않았다.
- 일반 회귀 검사 51개 묶음·321개 검사와 TypeScript 검사를 통과했다. 별도 DB/인증 환경을 요구하는 기존 Jest 통합 검사는 일반 검사 명령에서 제외하고 이번 SQL 통합 검증과 구분한다.
- 브라우저 예시에서 자동 연결·클립 이미지 미리보기·동의 전 게시 차단·취소 후 초기화·동의 후 완료·신규 제출 0건 안내를 확인했다. 예시 페이지는 운영 빌드에서 404가 되어야 한다.
- 보안 점검에서 새 함수의 익명 실행 불가·빈 검색 경로를 확인했다. 인증 사용자용 권한 상승 함수 안내 1건 증가는 본인 확인을 수행하는 새 API에 해당하며, 기존 익명 함수/인증 설정 안내는 이번 변경으로 추가되지 않았다. 기존 P0-10 후속 확인은 완료 처리하지 않는다.

## 복구

문제가 있으면 먼저 웹을 이전 운영 배포로 복귀한다. 기존 함수와 자료 구조를 유지하므로 새 자료를 삭제하거나 일괄 이관할 필요가 없다. 새 함수는 기존 웹에 영향을 주지 않아 남겨둘 수 있으며, 제거가 필요하면 새 웹 호출을 중단한 뒤 해당 함수만 제거한다. 실제 자료·심사 기록·공개 범위를 복구 편의로 삭제하거나 변경하지 않는다.
