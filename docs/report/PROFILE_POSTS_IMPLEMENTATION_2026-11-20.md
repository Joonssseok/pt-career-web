# 게시판 작성 및 영상 캡션 후속

## 게시글 확장 도구 모음 후속

- 사용자 첨부 화면을 기준으로 기존 Tiptap 게시글 편집기에 두 줄 도구 모음을 연결했다. 글꼴(기존 승인 본문체·제목체), 제목 단계, 크기, 굵게·기울임·밑줄·취소선, 글자색·형광펜, 네 방향 정렬, 목록·들여쓰기, 인용·코드·구분선, 링크, 특수문자·이모지, 본문 찾기를 제공한다. 사진·GIF·유튜브는 기존 삽입·크기 조절·사진 자르기 경로를 재사용한다.
- 표는 머리글 포함 3×3 삽입, 행·열 추가/삭제, 머리글 전환, 셀 병합/나누기, 표 삭제와 열 너비 조절을 지원한다. 저장 형식에 맞춰 표 안이나 목록·인용문 안의 중첩 표 삽입은 막는다. 임의 HTML 입력·설문·일반 파일 첨부는 추가하지 않았다.
- 게시글 전용 문서 검증·표시를 확장하고, 같은 승인된 저장 범위의 검증 함수 변경 `20261120110823_profile_post_editor_tools`를 운영 저장 구조에 적용했다. 기존 소개·상세소개 검증, 저장 자료, 테이블/저장소 접근 권한은 변경하지 않았다. 새 검증 보조 함수는 방문자·회원 직접 실행 권한이 없다.
- 새 서식은 허용 목록으로 검증한다. 링크는 HTTP/HTTPS만 허용하고 인증정보 포함 주소·스크립트 주소를 거부한다. 사진은 기존 소유 파일 검사를 유지하며, 표·인용 내부로 첨부물을 숨겨 이 검사를 우회할 수 없다. 방문자 표시는 검증된 React 요소만 사용한다.
- 격리 PostgreSQL에서 새 문서/JS 일치/표·링크·소유권·발행본 보존 176검사와 새 검증을 적용한 기존 게시판 190검사를 통과했다. 운영 보안 점검은 변경 전후 같은 5개 항목이며 새 경고가 없다. 기존 보안 후속 작업을 해결했다고 표시하지 않는다.
- 로그인된 별도 개발 미리보기에서 표 삽입·유튜브 썸네일·사진 선택·링크·특수문자 입력을 확인했다. 이 경로는 저장 연결을 끈 화면이며 실제 회원 계정에 시험 글·사진을 저장하거나 발행하지 않았다. 390px 화면에서는 두 줄 도구 모음만 가로로 이동하며 문서 전체의 가로 넘침은 없다. 실제 휴대폰 검증과 운영 실파일 쓰기 검사는 수행하지 않았다.
- 앱 커밋·푸시·배포 및 온라인 현황판 게시는 수행하지 않았다. 실제 작성 경로는 기존 승인된 저장 연결을 사용하며, 개발용 `/preview/post-editor`는 저장하지 않고 운영 빌드에서 접근을 차단한다.

## 사용자 요청과 현재 상태

- 직전에는 영상 저장1차만 승인되어 게시판은 준비 안내였음. 이번 요청에 따라 게시판 작성 기능을 준비한다.
- 영상은 제목 아래 여러 줄 설명(캡션)을 입력·저장·표시한다. 기존 영상과 권한을 유지하고 오래된 수정 충돌 검사도 유지한다. 큰 영상 전용 검색칸은 제거하며 프로필의 돋보기 검색은 유지한다.
- 캡션 확장 `20261120100420_profile_video_captions`는 사용자 요청한 같은 영상 저장 범위에 적용했다. 운영 저장 구조와 로컬 미리보기만 연결했고 앱은 배포하지 않았다.

## 게시판의 검토 가능한 결과

- 공개 프로필 소유자에게 글쓰기, 마이페이지에 내 글·영상 경로를 제공한다. 작성창은 기존 Tiptap 공식 편집기를 재사용하고 제목·본문·사진/GIF·유튜브 배치·분류·태그·공개 선택·내용 미리보기를 제공한다. 게시판의 사진·영상 수에는 상세소개20개 제한을 적용하지 않는다. 파일 전송은 공급자의 기술 한도를 따르며 무한 인프라를 보장하지 않는다.
- 글쓰기·임시 저장·발행을 구분한다. 초안 자동 저장은1.5초 입력 중단 뒤 수행하며 새 빈 화면만 열었다고 초안을 만들지 않는다. 발행된 글을 수정할 때 자동 저장으로 공개 내용을 덮어쓰지 않는다. 저장 실패 후 나가기로 입력이 사라지지 않도록 막고, 저장 후 나가기 중에는 입력을 잠근다.
- 게시판 목록은 블로그형·목록형·앨범형과 분류 선택, 임시 저장 모음을 제공한다. 홈에는 공개 글이 있을 때만 최대3건을 요약하고 글 주소에서 기존 프로필 틀 안에 본문을 표시한다. 공감/댓글은 제외한다.
- 사진은 새 비공개 전용 저장소에만 보관한다. 서식 문서는 기존 허용 목록 검증을 재사용하고 임의 HTML/외부 사진/임베드 HTML은 저장하지 않는다. 이미지 응답은 매번 현재 공개 조건을 검사하고 no-store로 반환한다.
- 운영 저장 연결 전의 실제 작성창은 편집·미리보기만 가능하며 저장되지 않는다는 안내를 표시한다. 발행/임시 저장 완료라고 가장하지 않는다.

## 새 운영 연결 승인 대상

새 게시글/사진 저장소와 본인/방문자의 접근 권한을 추가하므로 `docs/SECURITY_OPERATING_RULES.md`에 따라 영상1차와 별도의 이 범위를 확인받는다. 앱 배포는 포함하지 않는다.

1. 회원에게 연결된 게시글의 초안과 발행본, 제목·본문·분류·태그·공개 상태·시각·관리자 숨김을 저장한다. 프로필 판을 바꿔도 유지한다.
2. 현재 공개 대표 프로필을 가진 본인만 새 글/사진 저장·수정·발행·삭제한다. 비공개 전환은 기존 자료를 보관하고 방문자의 글·사진·목록·검색 접근을 차단한다. 임시 저장·나만 보기·관리자 숨김 자료는 방문자에게 없는 항목과 동일하게 응답한다.
3. 본인이 발행한 전체 공개 글과 첨부 사진만 사전 심사 없이 표시한다. 관리자 숨김을 일반 회원이 해제할 수 없다. 발행은 명시적 동작이고 새 저장 구조 연결만으로 기존 글/프로필을 자동 공개하지 않는다.
4. 게시글 삭제 및 기존 유예기간 뒤 계정 최종 삭제 시 새 게시글의 첨부 사진만 정리한다. 비공개 전환 때는 정리하지 않는다. 비공개 정리 대기열에서 고른 해당 신규 버킷의 파일만 기존 서버 작업 권한으로 제거하고 실패하면 재시도한다. 이미 사용한 파일 ID는 재사용하지 않아 삭제 대기 파일을 다른 계정이 가져갈 수 없게 한다.
5. 기존 다모아50MiB·상세소개20MiB·프로필·원본·이력 심사·다른 저장소는 유지한다. 앱 배포·기존 자료 삭제·다른 회원 자료 수정은 포함하지 않는다.

복구: `supabase/rollback/profile_posts.sql`로 신규 글/사진 접근만 회수하고 모든 저장 자료를 남긴다. 다른 버킷의 정책과 기존 기능은 유지한다.

## 문서·검증

- 회원 작성 게시물의 사전 심사 없음·작성자의 권한 및 내용 책임과 비공개 보관 기준, 수집 항목 및 유튜브 썸네일/플레이어의 외부 접속을 약관/처리방침 로컬 초안에 추가했다. 이미 있는 신고·숨김 기준을 유지하고 운영자의 법령상 책임을 면제하지 않는다. 법률 검토 완료나 운영 공지/동의 갱신 완료로 표시하지 않는다.
- 작성자 책임과 운영자 면책을 혼동하지 않도록 [약관법 제7조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0007&lsiSeq=260021&urlMode=lsScJoRltInfoR), [저작권법 제103조](https://www.law.go.kr/LSW/lsInfoP.do?lsId=000798)를 참고했다. 의료 광고 표현의 전문 검토와 관리자 숨김 알림 방식은 별도 후속이다.
- 실제 회원 계정에는 확인용 글·사진·영상을 저장하거나 발행하지 않는다. 허용 목록/권한/공개 전환/오래된 수정/정리 동작은 격리된 가상 자료로 검사한다. 실제 모바일 기기·한글 입력/큰 글의 성능·운영 실제 업로드 확인은 별도다.

상태: 게시판 운영 저장 구조 미적용·앱 미배포·온라인 현황판 미게시. 최종 검사 결과와 승인은 후속 항목에 기록한다.

## 최종 로컬 검증

- 영상 캡션 포함 격리 PostgreSQL98검사, 게시판·저장소·정리·접근 회수 복구까지 격리 PostgreSQL190검사를 통과했다. 실제 운영 DB에 게시판/사진 저장 구조를 적용하지 않았으며 실제 회원 자료로 쓰기 검사를 하지 않았다.
- 관련 화면·입력·기존 편집기·게시판 목록/공개 제외 검사10묶음78항목과 타입 검사를 통과했다. 앞서 기록한190검사는 실제 허용 목록 검증 함수도 포함하며 모형 검증 함수를 운영 안전성 증거로 쓰지 않는다.
- 실제 로그인된 로컬 공개 프로필에서 영상 검색칸 없음·영상 설명 입력란을 확인하고, 게시판의 글쓰기 버튼으로 기존 Tiptap이 적용된 독립 작성창에 진입했다. 미리보기임을 표시하고 저장/발행 최종 버튼은 연결 승인 전 비활성화했다. 사용자 데이터 입력/저장/발행 없이 화면만 확인했다.
- 정리 대기열은 신규 버킷의 더 이상 참조하지 않는 파일 경로만 서비스 전용 처리 함수로 제공한다. 저장소 삭제 성공 뒤 확인 처리하고 실패는 대기 상태로 남겨 재시도한다. 완료 후에도 개인 계정 정보 없는 불투명 파일 식별자 표식을 남겨 재사용·과거 파일 인수를 막는다.
- 복구 검사는 게시글·파일·저장소·정리 대기열 건수 보존, 신규 읽기/쓰기/정리 호출 차단과 기존 버킷 열람 유지를 확인했다. 기존 보안 후속 작업이나 실기기 검증을 완료했다고 표시하지 않는다.

## 운영 저장 연결 승인·적용

- 사용자가 준비한 게시판 저장·공개·삭제 정리 범위를 별도로 승인했다. 같은 범위의 신규 저장 구조 `20261120102049_profile_posts`를 운영 프로젝트에 적용하고 로컬 파일명도 같은 버전으로 맞췄다. 앱 배포·커밋·푸시·온라인 현황판 게시는 수행하지 않았다.
- 운영 조회에서 신규 세 테이블의 RLS 활성화, anon 직접 조회/생성 차단, authenticated 직접 테이블 쓰기 차단, 일반 회원의 파일 정리 함수 호출 차단, 새 사진 버킷 비공개를 확인했다. 실제 회원의 게시글·첨부 사진은0건이며 확인용 자료를 만들지 않았다.
- 로그인된 로컬 새 글 작성창을 입력 없는 상태에서 다시 열어 편집기 정상 표시와 임시 저장 버튼 활성화, 이전 미연결 안내 제거를 확인했다. 빈 작성창을 열기만 해서는 초안이 자동 생성되지 않는다. 실제 사용자 자료의 쓰기·발행을 시험 목적으로 수행하지 않았다.
- 운영 보안 점검의 신규 항목은 직접 테이블 정책/권한 없이 제한된 함수로만 접근하는 비공개 테이블3개의 INFO 안내뿐이며 새 WARN/ERROR는 없다. 기존 경고나 기존 P0-10 후속을 해결했다고 표시하지 않는다.
- 자료의 실제 저장/업로드/비공개 전환/정리 전체 흐름은 격리 가상 PostgreSQL190검사 및 화면·입력78검사에서 확인했다. 실회원 파일을 사용하는 운영 쓰기 검사와 실제 휴대폰 검증은 수행하지 않았으며, 앱 운영 화면은 배포 전까지 기존 버전이다.
