# 게시판·영상 작성 결정 및 영상 1차 연결 범위

상태: 사용자 결정 기록 / 영상1차 저장 연결 승인 및 적용. 앱 배포 없음. 구현·검증 범위는 `PROFILE_VIDEOS_IMPLEMENTATION_2026-11-20.md`를 따른다.

기준: 원본 작업 폴더의 `docs/report/profile-template-handoff/POSTS_HANDOFF_2026-11-20.md`, `posts-mock.html` 및 사용자의 후속 8개 답변. 인계서는 시안/제안이며 이 문서의 사용자 결정과 현재 코드 확인을 우선한다.

## 사용자 결정

1. 공감·댓글은 1차에서 제외한다.
2. 마이페이지의 ‘내 글·영상’ 바로가기는 둔다.
3. 후속 답변 ‘상세소개만 저장공간 제한 두고 나머지는 제한두지 마’에 따라 상세소개 전용 저장공간은 기존 20MiB를 유지한다. 새 게시글의 사진에는 별도 상품상 용량·장수 제한을 두지 않고, 글·영상 목록에도 총 등록 개수 제한을 두지 않는다. 기존 다모아 50MiB 한도는 이번 새 게시판·영상 범위에서 변경하지 않는다. 유튜브 목록은 파일을 업로드하지 않고 ID만 저장한다. 요청 크기·파일 형식·문서 구조 등의 입력 검증과 페이지 단위 조회는 유지하며 이를 총 등록 한도로 표현하지 않는다. 호스팅/저장 서비스의 기술적 전송 제한을 무한 저장 보장으로 안내하지 않는다.
4. 영상은 외부 이동 대신 사이트 안에서 재생한다.
5. 썸네일은 유튜브에서 직접 불러오고 우리 저장소에 복제하지 않는다.
6. 공개 대표 프로필을 가진 회원만 새 글·영상 작성 및 발행을 사용할 수 있다. 이후 비공개로 바뀌면 기존 글·영상은 보존하고 방문자의 목록·개수·검색·직접 주소·관련 미디어 접근을 차단한다. 소유자의 보관 내역 조회와 공개 사용 가능 여부 안내를 분리하며 비공개 상태의 새 작성은 서버에서도 거절한다.
7. 관리자 숨김 시 별도 알림 방법은 보류한다. 알림이 정해지지 않았다고 관리자 숨김/비공개 보호까지 생략하지 않는다.
8. 심사 없는 게시, 작성자의 권리·내용 책임, 신고 및 운영 기준에 따른 숨김 조항을 약관에 추가하는 방향에 동의했다. 실제 기능 제공 시점에 맞춰 문서를 수정한다. 포괄적인 운영자 면책이나 치료 효과 보장 문구는 만들지 않으며 법률 검토 완료로 표시하지 않는다.

## 현재 코드에서 확인한 것

- `ProfileTemplate.tsx`에 홈·상세정보·이력·게시판·영상 탭이 이미 구현되어 있다. 현재 브랜치의 홈 챕터 후속 수정은 아직 로컬 상태다.
- `ProfileContentChapter.tsx`는 게시판/영상 빈 상태와 작성자용 준비 안내만 제공한다. 데이터 저장 기능은 없다.
- `lib/profile-versions/detail-document.ts`의 `youtubeVideoId`는 허용 유튜브 호스트와 HTTPS를 검사해 11자 ID를 추출한다. 인계서의 새 파서를 중복 구현하지 않는다.
- `components/profile-editor/YoutubeVideo.tsx`는 유튜브 썸네일을 직접 표시하고 클릭 시 youtube-nocookie 플레이어를 연다. 기존 상세소개 너비 설정과 재생 방식을 재사용한다.
- 상세소개는 허용 목록의 JSON 문서를 검증하고 React로 출력한다. 인계서의 ‘서식 검증 도구가 전혀 없다’는 진단은 현재 작업 브랜치에는 해당하지 않는다. 게시판 확장 시 같은 검증 경계를 재사용하되 링크 등 추가 요구사항은 별도로 검증한다.
- 공개 프로필은 `public_expert_detail` 및 대표 프로필 조회를 사용한다. 공개·회원 표시·승인·정지·탈퇴 상태를 모두 확인하는 현재 공개 조건을 영상에서도 유지해야 한다.
- 기존 `youtube_url` 채널 링크와 상세소개 안의 영상 배치는 보존한다. 새 회원별 영상 목록으로 자동 복사하거나 자동 발행하지 않는다.

## 1차 영상: 검토 가능한 저장·권한 범위

이 범위에 대해 사용자가 영상 저장 연결을 승인했다. 게시판의 새 글/사진 저장 권한은 이 묶음에 포함하지 않는다.

### 저장 대상

회원별 영상 1건마다 고유 ID, 소유 회원 ID, 유튜브 ID(정확히 11자), 제목(최대 80자), 공개 상태(public/private), 관리자 숨김 여부, 생성·수정 시각을 저장한다. 프로필 버전 ID에 종속시키지 않는다. 연결 검토에서 기존 탈퇴 흐름이 유예기간 뒤 계정을 최종 삭제하는 것을 확인했다. 이때 새 영상 메타데이터도 함께 정리되도록 새 테이블만 계정 삭제 흐름에 연결하며 기존 프로필·파일·계정 삭제 정책은 바꾸지 않는다. 단순 비공개 전환에서는 삭제하지 않는다.

영상 원본/썸네일/유튜브 전체 응답/사용자가 넣은 iframe·HTML·비밀키는 저장하지 않는다. 공개 목록 응답에 소유 회원 ID와 내부 관리 정보를 노출하지 않는다. 별도 영상 파일 저장소나 외부 사진 업로드 권한은 추가하지 않는다.

### 접근 동작

| 동작 | 기준 |
|---|---|
| 소유자 보관 목록 | 로그인한 본인 자료만 조회. 비공개 프로필 전환 후에도 보존 여부 확인 가능 |
| 새 등록·수정·발행 | 실제 로그인 본인 + 현재 공개 가능한 대표 프로필 검증. 정지·탈퇴 요청 계정 차단 |
| 방문자 목록·직접 조회 | 현재 공개 가능한 대표 프로필 + 영상 전체 공개 + 관리자 숨김 아님. 조건을 벗어나면 없는 항목과 동일한 응답 |
| 타인 변경 | 항상 거절 |
| 관리자 숨김 | 기존 관리자 판정 사용. 일반 회원이 숨김 값을 임의 변경하거나 재발행으로 우회할 수 없음 |
| 비공개 전환 | 글·영상을 삭제하거나 공개 상태 값을 일괄 덮어쓰지 않음. 조회 시점의 프로필 공개 조건으로 차단 |
| 대표 프로필 판 교체 | 같은 회원의 글·영상 유지. 새 대표 프로필의 공개 조건으로 조회 판단 |

소유자 검증은 입력 회원 ID나 화면 표시 상태가 아니라 인증된 회원과 실제 저장 상태를 기준으로 한다. 권한 검사는 DB에서도 수행한다. 응답은 페이지 단위로 가져오되 페이지 크기를 총 등록 가능 개수 제한으로 사용하지 않는다.

### 화면·외부 호출

- 공개 프로필의 소유자에게만 ‘영상 추가’와 관리 동작을 표시하고 마이페이지에서 ‘내 글·영상’으로 이동한다. 공개 전 회원은 공개 설정 안내만 표시하고 새 작성은 막는다.
- 추가 창은 유튜브 주소 → 썸네일 → 제목 확인/수정 → 공개 상태 선택 → 저장 순서다. 빈 제목과 유튜브 외 주소는 거절한다.
- 자동 제목은 검증된 ID로 서버에서 고정된 YouTube oEmbed 주소만 요청한다. 임의 주소 요청·리디렉션 추적은 허용하지 않는다. 시간/응답 크기를 제한하고 실패하면 직접 제목을 입력한다. 외부 응답의 HTML은 사용하지 않는다.
- 썸네일/플레이어는 기존 구현을 사용한다. 유튜브의 임베드 차단·비공개·삭제·연령 제한은 사이트가 우회할 수 없으므로 재생 불가 안내를 제공한다.
- 공개 영상만 홈 영상 챕터/영상 탭/프로필 내 검색에 포함한다. 미등록 Home 챕터 생략 규칙을 유지한다.
- 관리 페이지/소유자 자료는 공유 캐시에 담지 않는다. 비공개 전환 후 새 요청이 과거 공개 캐시로 남지 않도록 목록·검색·직접 조회의 캐시 경계를 함께 검증한다.

### 검증과 복구

가상 계정으로 비로그인·본인·타인·정지·비공개 전환·관리자 숨김·프로필 판 교체를 검사한다. 비공개 직접 주소/목록/검색/개수 누출 없음, 잘못된 유튜브 주소 거절, 제목 조회 실패 후 수동 입력, 모바일 표시, 기존 상세소개 재생 보존을 확인한다. 실제 회원에게 가짜 영상이나 게시물을 등록하지 않는다.

복구 시 새 영상 기능의 호출·권한을 회수하고 준비 안내 화면으로 되돌린다. 저장된 영상 내역과 기존 프로필/상세소개/파일은 삭제하지 않는다. 테이블을 지우는 방식의 롤백은 하지 않는다.

## 2차 게시판과 남은 작업

영상 1차 이후 별도 범위를 보고한다. Tiptap 기반 편집기 재사용, 글/카테고리/사진 저장, 임시 저장, 나만 보기, 공개 글 고유 주소, 본문/미디어 검증, 관리자 숨김, 이용약관과 개인정보 처리방침의 실제 수집·외부 접속 안내를 함께 검토한다. 의료 광고의 적법성을 자동으로 보장하거나 약관에 책임 전가만으로 해결됐다고 표시하지 않는다.

현재 문서는 결정과 승인 범위를 기록한다. 영상1차의 실제 적용/검증 결과는 별도 구현 보고서를 따른다. 앱 배포·온라인 현황판 게시·게시판 저장 승인을 뜻하지 않는다. 기존 미해결 보안 과제도 별개다.
