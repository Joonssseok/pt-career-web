# 회원별 영상 목록 · 1차 연결

범위: `PROFILE_POSTS_SCOPE_2026-11-20.md`의 영상 1차에 대해 사용자가 저장 연결을 승인했다. 게시판 저장·앱 배포는 승인 범위에 포함하지 않는다.

## 구현

- 회원별 유튜브 ID·제목·공개 상태·관리자 숨김·생성/수정 시각을 별도 비공개 스키마에 저장한다. 기존 프로필 판이나 상세소개를 덮어쓰지 않는다.
- 공개 프로필 영상 탭 및 마이페이지 ‘내 글·영상’에서 본인만 추가·수정·공개 전환·삭제할 수 있다. 삭제는 사용자 확인 후 본인 영상 메타데이터에만 적용하며 유튜브 원본을 지우지 않는다.
- 공개 대표 프로필이 없는 회원은 새 등록·수정할 수 없다. 기존 영상은 보관하고 본인 보관 목록은 읽기 전용으로 제공한다. 정지/탈퇴 요청/미확인 계정은 본인 관리도 제한한다.
- 방문자 조회는 현재 프로필 공개 조건·영상 전체 공개·관리자 숨김 아님을 매번 검사한다. 나만 보기 및 숨김 항목의 제목은 공개 검색에 포함하지 않는다.
- 유튜브 주소는 기존 허용 호스트/11자 ID 검증을 재사용한다. 자동 제목은 고정된 YouTube oEmbed 경로만 요청하고 응답 크기/시간/리디렉션을 제한한다. 실패하면 제목을 직접 입력한다. 외부 HTML은 사용하지 않는다.
- 기존 썸네일/사이트 내 재생기를 재사용한다. 영상 목록은 총 등록 한도 없이 페이지 단위로 조회하며 제목 검색은 첫 페이지 밖의 저장 목록도 검색한다. 상세소개20MiB·다모아50MiB는 유지한다.
- 홈은 설명 → 이력 → 게시판 → 영상 → 근무지 순서 중 기록된 영역만 표시한다. 영상 홈 요약은 최대3개 표시이며 등록 개수 제한이 아니다. 상세소개 영상·채널 링크는 보존한다.

## 검증 기록

- 격리된 가상 PostgreSQL에서 93개 권한/입력/공개 조건/검색/대표 판 교체/총100개 초과 등록/오래된 수정 충돌/최종 탈퇴 정리/복구 검사를 통과했다. 복구 후 가상107건이 보존됐다. 실행기: `node tests/helpers/check-profile-videos-sql.mjs ../introduction-sql-check/node_modules/@electric-sql/pglite/dist/index.js`.
- 공개RPC는 invoker 래퍼, 실제 처리는 비공개 스키마의 제한된 함수다. 직접 테이블 권한은 없고 RLS·빈 search_path·실제 로그인 소유자·프로필 행 잠금을 사용한다. 일반 회원이 관리자 숨김을 해제할 수 없다.
- 기존 프로필 전체 행을 해시로 반환하는 검증은 자동 승인 검토가 거절해 수행하지 않았다. 해당 방식으로 원본 보존을 확인했다고 주장하지 않는다. 신규 SQL의 기존 자료 변경 없음과 격리 테스트로 검증 범위를 구분한다.

## 적용 상태 및 남은 확인

- 승인한 운영 프로젝트에 영상 전용 신규 저장 구조 `20261120094453_profile_videos`를 적용했고 같은 버전으로 로컬 파일명을 맞췄다. 운영 조회로 RLS 활성화, 비로그인 쓰기 거절, 직접 테이블 읽기/쓰기 권한 없음, 새 영상0건을 확인했다. 기존 프로필·파일·상세소개·권한을 변경하는 SQL은 포함하지 않았다.
- 관련7개 검사 묶음54항목과 타입 검사를 통과했다. 로그인된 로컬 공개 프로필의 영상 추가·마이페이지 내 글/영상 관리 경로를 확인했다. 공식 유튜브 개발자 영상의 주소로 자동 제목·썸네일과 클릭1회 후 실제 사이트 내 재생/경과시간 진행을 확인했다. 저장은 누르지 않고 취소했으며 실제 영상 내역에 예시를 추가하지 않았다.
- 운영 보안 점검 전후에 새로운 경고는 없다. 신규 INFO1건은 의도적으로 직접 정책/테이블 권한 없이 제한된 함수를 통하는 비공개 영상 테이블의 RLS 안내다. 기존 경고는 이번 작업으로 해결했다고 표시하지 않는다.
- 앱 배포·커밋·푸시·온라인 현황판 게시는 진행하지 않았다. 열어둔 로컬 미리보기의 저장 동작은 승인한 실제 영상 저장 구조에 연결되어 있다.
- 실제 회원에게 검증용 허위 영상을 저장하지 않는다. 실기기·유튜브별 임베드 허용 여부·동시 연결의 잠금 경쟁은 별도 확인이다.
- 게시판 글/사진 저장·자동 임시 저장·약관의 게시판 책임/신고 조항은 별도2차 범위다. 관리자 숨김 알림 방식은 보류한다.
- 기존 탈퇴 유예기간 뒤 계정 최종 삭제 시 새 영상 메타데이터도 함께 정리되도록 새 영상 테이블에만 회원 참조를 연결한다. 기존 프로필·파일·삭제 정책은 바꾸지 않으며 단순 비공개 전환에서는 보존한다.
- 다른 창의 비공개 전환을 오래된 편집 내용이 다시 공개하지 않도록 수정 시각 일치 검사를 추가했다. 충돌하면 저장을 거절하고 목록 새로고침을 안내한다.
- 기존 개인정보 가리기 서버 검증/반려 사본 정리/P0-10 후속 문제를 이 작업의 완료로 처리하지 않는다.
# 영상 작성 화면 후속

- 영상 추가 아이콘은 게시글 작성과 같은 별도 `/my/content/videos/new` 화면으로 이동한다. 공개 대표 프로필의 본인만 접근하며 기존 서버 저장·공개 검증을 재사용한다.
- 영상 주소/썸네일 미리보기를 먼저 배치하고 제목·캡션·공개 설정을 뒤에 둔다. 기존 영상 수정 팝업과 같은 입력·검증 로직을 공유한다. 캡션은 기존 일반 텍스트 저장 형식이다.
- 새 작성창에는 자동 저장을 추가하지 않는다. 명시적 저장 뒤 영상 탭으로 돌아가고, 실패하면 입력을 유지한다. 입력한 내용이 있을 때 나가기 확인과 새로고침 경고, 중복 저장 방지를 제공한다.
- 관련17검사 및 타입 검사 통과. 실제 로그인된 영상 추가 아이콘에서 새 작성 경로로 이동하는 것을 확인했으며 실회원 영상 저장/발행은 하지 않았다. DB 변경·앱 배포·온라인 현황판 게시는 수행하지 않았다.
