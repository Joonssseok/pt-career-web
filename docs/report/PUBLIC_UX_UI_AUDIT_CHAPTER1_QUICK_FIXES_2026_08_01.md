## 1-1. 전문가 목록 필터 미작동 (원본 P0)

### 원인
`ExpertFilters.tsx`의 `updateFilter()`가 `useSearchParams()`로 읽은 값을
클로저로 캡처해 새 URL을 만드는 구조였다. 그런데 `router.push()`는
`window.location.search`와 `useSearchParams()`를 **동기적으로 갱신하지
않는다** — 실측 결과 반영까지 수십 ms가 걸린다. 그 사이에 사용자가 두 번째
필터를 연속으로 바꾸면, 두 번째 `updateFilter()` 호출이 아직 첫 번째 변경을
반영하지 못한 옛 `searchParams`를 기준으로 URL을 다시 만들어 **첫 번째
필터가 통째로 사라진다.**

재현 절차(Claude in Chrome으로 실제 프로덕션 `pt-career-web.vercel.app`에서
확인):
1. 단일 필터 변경(예: 직군만 선택)은 정상 동작 — 되돌아가지 않음.
2. 직군 선택 직후(대기 없이) 지역을 선택 → 최종 URL이 `?region=경기`만
   남고 `profession` 파라미터가 사라짐. 직군 select도 "전체 직군"으로
   돌아감. **원본 감사의 "선택값이 전체 직군으로 되돌아간다"와 정확히
   일치하는 재현.**

`window.location.search` 기준으로 바꾸는 1차 시도도 같은 이유로 실패했다
(이 값도 비동기 반영이라 동일한 경쟁 상태가 재현됨 — 직접 계측: `push()`
직후 0ms/microtask 시점엔 `location.search`가 그대로, 약 50ms 후에야 반영).

### 수정
`app/experts/ExpertFilters.tsx`: 필터 상태를 React state(`paramsString`)로
관리하도록 변경.
- 사용자가 필터를 바꾸면 `setParamsString`의 함수형 업데이트로 직전 상태
  위에 누적 — React가 이벤트를 배치 처리해도 항상 최신 상태를 기준으로
  하므로 두 번째 변경이 첫 번째를 덮어쓰지 않는다.
- `paramsString`이 커밋된 URL(`searchParams`)과 달라지면 별도 effect가
  `router.push()`로 반영.
- 뒤로/앞으로 가기 등 외부 URL 변경은 `searchParams` → `paramsString` 동기화
  effect로 흡수.

### 검증
로컬(dev, Fast Refresh 적용 확인) + 프로덕션 데이터 대상으로 Claude in
Chrome을 통해:
- 단일 필터 변경 → 정상 유지 (회귀 없음)
- 직군+지역 연속 변경(대기 없음) → 최종 URL에 `profession`+`region` 둘 다
  반영, 두 select 모두 올바른 값 유지
- 직군+지역+전문분야 3개 연속 변경(대기 없음) → 3개 모두 정확히 결합

**원본 P0 등급 유지, 근본 원인은 데이터 부재가 아니라 클라이언트 경쟁
상태였음을 확인.**

## 1-2 / 1-4. 외부 문의 링크 버그 + 라벨 모호함 (원본 P0 / P1)

### 원인 확인
프로덕션 DB 조회로 원본 감사를 재현: 승인된 프로필(김준돌)의
`workplace_external_contact_url`이 `"02-1234-5678"`(전화번호)로 저장돼
있었다. 원인은 입력 단계(`WorkplaceSection.tsx`)의 라벨 "공식 문의처"·
placeholder "예: 02-1234-5678"이 전화번호 입력을 유도하는데, 공개 페이지는
같은 값을 `href`에 그대로 꽂고 "외부 문의(카카오톡 등)"로 노출 — 입력과
노출 사이에 형식 검증이 전혀 없었다.

### 수정
- `app/actions/workplace.ts`의 `saveWorkplace()`: `officialContact` 값이
  있으면 `new URL()`로 파싱해 `http:`/`https:` 프로토콜인지 검사, 아니면
  `{ ok: false, error: '...http(s)로 시작하는 링크...' }`로 저장을 거부.
  (자동 보정이 아니라 거부를 택함 — "02-1234-5678"처럼 URL로 해석 불가능한
  값을 억지로 `https://` 접두어만 붙이면 더 이상한 깨진 링크가 되므로.)
- `components/profile-sections/WorkplaceSection.tsx`: 라벨을
  "카카오톡 오픈채팅 등 문의 링크", placeholder를
  `https://open.kakao.com/o/...`, `type="text"` → `type="url"`,
  안내문을 "전화번호가 아닌 http(s):// 링크만 입력" 으로 정정. 이 한 번의
  수정으로 1-4(라벨 모호함)도 함께 해결된다.
- 실패 시 에러 메시지는 `EditForm.tsx`의 기존 섹션 저장 실패 배너
  (`근무기관(에러메시지)` 형식)로 그대로 노출되므로 별도 UI 배선 불필요.

### 기존 잘못 저장된 값 정리 — 하지 않음 (판단 지점)
프로덕션에서 형식이 틀린 `external_contact_url`을 가진 행은 김준돌
프로필 1건뿐이었다. 이 프로필은 사용자가 별도로 "건들지 말라"고 명시한
대상이라, 데이터 정리 대상에서 제외했다. 다른 승인 프로필(김준석)은
`external_contact_url`이 `NULL`이라 정리할 대상이 없었다. **즉 이번
세션에서 실제로 수정된 기존 데이터는 없다** — 검증 로직과 라벨만
정정했고, 향후 잘못된 값이 입력되는 것을 막는 데 집중했다.

### 검증
코드 검토로 로직 정확성 확인(`tsc`/`build` 통과). 인증이 필요한 실제
폼 제출 클릭 테스트는 로컬에 시드 계정이 없어 생략했다 — 배포 후 실제
계정으로 "전화번호 저장 시도 → 거부 메시지 노출"을 재확인하는 것을
후속 검증으로 남긴다.

## 1-3. 테스트성 공개 프로필 데이터 정리 (원본 P0) — 데이터 변경 없음

프로덕션 승인 프로필은 2건(김준돌, 김준석)뿐이다. 김준돌 프로필의
헤드라인/소개("한 손으로 세계를 지배한다...", "저는 신의 아들입니다...")가
원본 감사가 지적한 문제 콘텐츠이지만, 사용자가 이 프로필을 명시적으로
제외해 손대지 않았다. 김준석 프로필의 헤드라인/소개("10년 경력의 필라테스
강사입니다", "소비자 중심의 맞춤형 운동 프로그램 제공")은 정상적인
내용이라 정리할 필요가 없었다. **결과적으로 1-3은 코드/데이터 변경 없이
종료.**

## 1-6. 근무기관 섹션 "정책 미확정" 문구 정정 (신규 발견, 지시서 범위 외)

### 추가로 확인한 사실
`public_expert_list` 뷰 정의를 직접 조회한 결과, `workplace_region`/
`workplace_center_name` 노출 조건은 **처음부터** `w.is_location_public AND
w.owner_visible`뿐이었다 — 관리자 승인이라는 개념 자체가 이 필드엔 애초에

폐지(PR #55) 이전부터 **애초에 사실과 달랐던 문구**였다.

### 수정
`components/profile-sections/WorkplaceSection.tsx`에서 3곳 정정:
- "💡 개인 연락처: 항상 비공개 / 공식 연락처: 공개 정책 미확정" →
  1-2/1-4 수정에 포함해 새 안내문으로 교체(위 참고)
- "⏳ 근무지역 공개 정책은 운영팀 검토 중입니다" → 삭제
- "체크하면 PT Career 내 검색 시 지역 필터에 나타납니다. (운영팀 승인 후
  공개)" → "체크하고 저장하면 별도 검토 없이 즉시 PT Career 검색의 지역
  필터에 나타납니다."로 정정

## 1-9. 전문가 카드 빈값 처리 규칙 통일 (원본 P1의 로직 부분)

`ExpertCard.tsx`와 `[id]/page.tsx` 둘 다 "경력 N년 + 근무지역·기관" 메타
정보 줄이 `total_experience_years`와 `workplace_center_name`이 **둘 다
없을 때도** 빈 `<div>`가 렌더링되며 `mt-2`/`gap-2` 마진만 차지해, 필드
유무에 따라 카드 높이가 미세하게 들쭉날쭉해지는 문제가 있었다. 두 파일
모두 해당 블록을 `{(조건1 || 조건2) && (...)}`로 감싸 빈 블록 자체가
렌더링되지 않도록 수정. 상세 페이지(`[id]/page.tsx`) 쪽은 지시서 범위(카드)
밖이지만 동일한 버그 패턴이라 함께 수정했다(자체 판단, 아래 "지시서에
없어서 스스로 판단한 부분" 참고).

## 1-10. 카드 필드 노출 순서 조정 (원본 6.2/6.3절 중 기존 필드 재배치만)

`ExpertCard.tsx`에서 원본 감사 6.2절 권장 순서(이름 → 직군·총경력 →
근무지역·기관 → 전문분야)에 맞춰 "경력+근무기관" 메타 줄을 헤드라인보다
위로 옮겼다(기존: 이름 → 헤드라인 → 경력/근무기관 → 전문분야, 변경 후:
이름 → 경력/근무기관 → 헤드라인 → 전문분야). 새로운 시각 요소(검증
배지 등)는 추가하지 않았다 — 그 부분은 3-2(디자인팀 선행 필요)로 남아있다.

상세 페이지는 이미 "총경력·근무기관" 배지가 헤더 바로 다음에 위치해
권장 순서와 부합하므로 추가 재배치를 하지 않았다.

## 지시서에 없어서 스스로 판단한 부분

1. **1-9의 빈값 처리 버그를 상세 페이지(`[id]/page.tsx`)에도 동일하게
   적용.** 지시서는 "카드"로 범위를 좁혔지만, 상세 페이지에도 완전히
   동일한 버그 패턴(빈 메타 블록이 마진만 차지)이 있어 함께 고쳤다.
2. **1-2 기존 잘못된 데이터 정리를 생략.** 유일한 대상이 사용자가 명시적
   으로 제외한 김준돌 프로필이라 데이터는 그대로 두고 검증 로직/라벨만
   수정했다.
3. **URL 검증을 "저장 거부"로 결정** (지시서는 거부/자동 보정 중 판단을
   맡김). 전화번호처럼 URL로 해석 불가능한 값에 `https://`를 기계적으로
   붙이는 자동 보정은 더 이상한 결과를 만들 수 있어 명확한 에러 메시지로
   거부하는 쪽을 택했다.
4. **웹사이트/타이틀 메타데이터(`app/layout.tsx`)의 "내 주변"도 함께
   정정.** 지시서 1-5는 UI 문구만 언급했지만 SEO 타이틀/OG 태그에도 동일
   표현이 있어 일관성을 위해 함께 바꿨다.
