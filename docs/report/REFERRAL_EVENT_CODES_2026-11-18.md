# 운영자 발급 추천인·행사 코드

## 범위

- 회원별 초대 코드가 아닌 운영자 발급 행사 코드만 지원한다. 가입 시 선택 입력 또는 가입 후 로그인 정보·연락처에서 등록한다.
- Google·네이버 OAuth와 이메일 확인의 기존 callback URL에 행사 코드 힌트를 전달한다. 이메일 확인 링크로 다른 기기에서 가입을 마쳐도 힌트가 함께 전달된다. 이 값은 신뢰하지 않으며 인증 후 DB에서 유효성과 소유자를 검증한다.
- 계정당 1개만 등록한다. 같은 코드 재요청은 최초 시각을 보존하며 성공하고, 다른 코드로 변경하는 요청은 차단한다.
- 관리자만 행사 이름·코드를 발급하고 신규 등록을 중지/재개한다. 중지해도 기존 등록 이력은 유지한다. 일반 회원은 본인 등록 내역만 조회하며 타인의 등록 정보나 행사 목록을 조회할 수 없다.
- 현재 쿠폰·할인·포인트·유료 이용 권한을 지급하지 않는다. 혜택 조건·대상·가격·사용 기간·지급 기능은 별도 기획 대상이다. 등록 이력은 향후 혜택 검토의 근거로 사용할 수 있으며 기존 등록 자체가 지급 보장은 아니다.

## 보관과 권한

- 비공개 referral_private 스키마에 행사 정보와 계정별 등록 코드·등록 시각을 분리한다. 등록 회원 식별자는 기존 인증 계정 FK로 연결하고 계정 삭제 시 등록 이력도 삭제한다.
- 두 테이블에 RLS를 켜고 클라이언트 직접 접근을 허용하지 않는다. public 함수는 invoker이며 비공개 함수에서 인증 사용자·확인된 계정·정지/탈퇴 대기·관리자 여부를 다시 검사한다. 함수 search_path는 비운다.
- 일반 회원에게 지급 권한이나 타인 조회 권한을 추가하지 않는다. 관리자 여부는 기존 보호된 관리자 테이블을 조회하는 is_admin으로 확인한다. user_metadata는 권한 근거로 사용하지 않는다.
- auth 사용자 행 잠금 및 행사 행 공유 잠금으로 중복 등록과 행사 중지를 직렬화한다. 검증한 범위 밖의 다중 세션 경쟁은 아래 한계에 구분한다.
- 개인정보처리방침 공통 문서에 선택 수집 항목·목적·계정 삭제 시 정리 기준을 추가했다. 공개 프로필에는 코드 등록 이력을 표시하지 않는다.
- 권한만 회수하고 데이터를 보존하는 REFERRAL_ROLLBACK_DISABLE.sql을 준비했다.

## 검증 및 적용 상태

- 관련 Jest 5개 묶음 66개 검사 통과: 세 가입 경로 전달, 서버 인증·관리자 제한, 가입 후 등록, 잘못된 코드, 오류 은폐, 미리보기의 실제 처리 차단, 연결 실패 후 재시도.
- 기존 필수약관 동의 3개 검사도 통과했다.
- PGlite 격리 Postgres 검사 15개 통과: 실제 SQL 실행, 익명·미확인·정지 계정 차단, 관리자 사칭 차단, 직접 테이블 접근/RLS, 타인 조회 차단, 1회 등록·멱등성, 삭제 연쇄, 권한 롤백의 자료 보존.
- TypeScript 검사 및 diff 검사 통과. 개발 미리보기의 PC/390px 화면과 선택 입력/가입 후 입력/발급 화면을 확인했다. 390px에서 가로 넘침 없음.
- 실제 운영 회원의 가입·행사 발급·코드 등록·쿠폰 지급은 검증용으로 수행하지 않았다. 다중 세션 경쟁과 실제 소셜/메일 확인 왕복은 미검증이다. 운영 Site URL이 https://ptcareer.co.kr이고 기존 callback 허용 주소가 등록되어 있음을 읽기 전용으로 확인했으며 인증 설정은 변경하지 않았다.
- 사용자가 비공개 행사 코드/회원별 등록 저장·본인 조회·관리자 전용 발급/중지 범위를 승인했다. 승인 후 운영 DB에 referral_event_codes 변경을 적용했다. 서버에 기록된 버전 20261118075047에 로컬 migration 파일과 테스트 경로를 맞췄다.
- 운영 카탈로그에서 두 테이블의 RLS, 익명/회원 직접 테이블 권한 없음, 익명 함수 실행 불가, 비공개 내부 helper 실행 불가, public invoker/private definer와 고정 search_path를 확인했다. 행사 코드·등록 기록은 각 0건이다.
- 실제 로그인 계정의 로컬 계정 화면에서 운영 own_referral_status 조회와 관리자 화면의 list_referral_campaigns 조회가 정상 연결됐다. 시험 코드나 등록 기록을 만들지 않았다.
- 운영 보안 진단에는 새 테이블의 의도적인 RLS 무정책(직접 접근 금지) INFO 안내가 표시된다. 이를 해소하려고 테이블 조회 정책을 열지 않았다. 기존 보안 과제의 해결을 의미하지 않는다.
- 위 항목은 기능 구현 단계의 검증 기록이다. 이후 사용자가 추천인·행사 코드 및 계정 메뉴 통합의 커밋·푸시·병합·운영 배포를 요청했다. 최종 배포 결과는 PR과 현황판에 구분해 기록한다.
- 미리보기: http://127.0.0.1:3002/preview/referral. 개발 환경 전용이며 실제 가입·발급·등록을 하지 않는다.

## 릴리스 검증

- DB 쓰기 없는 Jest 74개 묶음/485개 검사, TypeScript, 격리 PGlite SQL 15개 검사 및 diff 검사 통과. 별도 Supabase 테스트 환경이 필요한 기존 통합 검사 6개 묶음은 실행하지 않았다.
- 코드 발급·중지/등록의 실제 운영 자료 변경 및 실제 신규 소셜/이메일 가입 왕복은 수행하지 않았다. 기존 PIN·탈퇴 확인과 가입 약관 동의 절차를 유지한다.
