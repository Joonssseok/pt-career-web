- 활성 분류 11개와 순서, 의료기사 대상 물리치료사, 병원 근무 제한 표시를 DB에서 확인했다. 사라진 두 분야의 남은 선택은 0건이며, 저장 경로 제약 4개와 적용 이력 1건을 확인했다.
- 전환 전후 비교에서 프로필 본체·직군 목록의 기존 정보·직군 선택·분야를 제외한 버전 내용·기존 저장 함수 권한이 일치했다. 비공개 백업의 RLS 및 방문자/회원/서비스 역할의 스키마 접근 차단을 확인했다.
- 실제 로그인된 `/my/profiles?profile=...` 기본정보에서 새 목록 11개가 나타나는 것을 확인했다. 기존 선택은 스포츠·컨디셔닝 / 자세·움직임 개선 / 부상 후 리커버리로 이어졌으며, 병원 근무는 자동 선택하지 않았다. 프로필의 다른 입력을 변경하거나 새 게시를 수행하지 않았다.
- 자동 보안 점검에서 새 비공개 백업 6개 테이블의 ‘RLS 활성·정책 없음’ 안내를 확인했다. 이는 직접 접근을 허용하지 않는 설계이며 접근 권한을 추가하지 않았다. 다른 기존 함수 관련 경고를 이번 작업의 보안 검증 완료로 간주하지 않는다.
- 공용 DB를 적용했으므로 기존 운영 앱도 DB를 읽는 분류 이름·선택에는 변경이 반영될 수 있다. 새 홈/안내/편집 구성의 앱 배포는 아직 하지 않았다.

공용 DB 적용 이력은 `20261123151048 / specialty_categories`이며, 준비 파일의 생성 시각(`20261123140856`)과 다르다. 후속 릴리스에서 이름과 적용 이력을 대조하고 새 데이터 변환을 중복 수행하지 않는다.

## 화면과 저장 조건

- 이름과 순서는 인계서 5장에 따른다. 홈은 DB의 활성 목록을 읽는다. 탭·묶음 제목·병원 근무 세부 분류는 추가하지 않는다.
- 선택은 합계 1~3개다. 병원 근무 하나만 선택해도 최소 조건을 충족한다. 네 번째 선택과 0개 저장은 막는다.
- 의료기사 여부는 직군의 메타데이터로 판단한다. 화면에서 특정 직군 주소를 하드코딩하지 않는다. 기존 물리치료사만 초기 대상이며 새로운 직군은 추가하지 않았다.
- 의료기사 직군을 해제하면 병원 근무 선택을 자동 삭제하지 않는다. 선택 해제 안내를 표시하고 본인이 해제하도록 한다.
- 직군과 분야의 저장 순서를 맞췄다. 의료기사로 변경할 때는 직군을 먼저, 의료기사에서 변경할 때는 분야를 먼저 저장한다. 첫 저장이 실패하면 뒤의 의존 저장을 실행하지 않는다.
- 홈·공개 프로필·전문가 카드에 병원 근무 안내를 표시한다. 해당 분야가 있는 프로필의 외부 문의 버튼은 숨기며, 개별 공개된 전화·이메일·주소는 기존 기준을 유지한다. 예약·결제 기능은 추가하지 않았다.

## 준비한 DB 전환과 복구

- 전환 파일: `supabase/migrations/20261123140856_specialty_categories.sql`.
- 복구 파일: `supabase/rollback/specialty_categories.sql`.
- `professions.is_medical_technician`, `specialties.medical_technician_only`를 추가하고 기존 분야의 이름·순서를 변경한다. 사라지는 두 행은 지우지 않고 비활성으로 남긴다.
- 두 분야의 기존 선택을 스포츠·컨디셔닝으로 합친다. 중복은 하나로 정리하며 기존 대표 여부·가장 앞선 순서·생성 시각을 보존한다. 공개/비공개가 충돌하면 비공개를 우선한다.
- 이미 게시된 분야 스냅샷만 새 이름·합쳐진 분야에 맞춘다. 이전 공개 응답과 일치하지 않던 항목이 전환 때문에 새로 공개되지 않도록 검사한다. 초안·소개·연락처·사진 등 다른 내용은 변경하지 않는다.
- 기존 저장 함수의 권한과 소유자·상태·개수 검사를 유지한다. 함수와 직접 테이블 쓰기 경로 모두 의료기사 조건을 확인한다. 직군을 바꿀 때도 마지막 의료기사 직군과 병원 근무가 어긋나는 저장을 막는다.
- 전환 전 값과 전환 후 값을 별도 비공개 스키마에 최소 범위로 보관한다. 일반 방문자·회원·서비스 역할에는 스키마 접근 권한이 없으며, 백업 테이블은 RLS를 켜고 공개 정책을 만들지 않는다.
- 복구는 이후 변경과 충돌하면 전체 중단한다. 새 병원 근무 선택, 변경된 분야·선택·게시 스냅샷·저장 함수가 있으면 덮어쓰지 않는다. 새 열과 비공개 백업은 보존하고 새 병원 근무 행은 비활성으로 남긴다.
- 운영 적용 시 이 전환과 앱 변경을 같은 릴리스로 다뤄야 한다. 코드만으로 운영의 분류 변경이나 저장 검증 적용이 끝났다고 보지 않는다.
