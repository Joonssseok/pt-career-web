## 3. 대표님이 정한 것

1. 묶음 이름("배우고 준비한 경험", "일하고 실천한 경험" 등)은 두루뭉술하다. 경력·학력 등 구체적인 분류 이름으로 나눈다.
2. 어떤 활동이든 같은 입력창인 것이 문제다. 분류마다 필요한 칸을 보여 준다.
3. 근무 기간은 고르는 방식으로 받는다.
4. 가독성과 심미성을 우선한다.

아직 정하지 않은 것은 8장에 있다. 정해지기 전에는 "권장"으로 적은 쪽으로 진행하지 말고 확인을 받는다.

## 4. 화면 구성

### 4-1. 보관함 (`damoa-list-mock.html`)

배치: 왼쪽 카드 320px(고정) + 오른쪽 목록 최대 660px. 900px 미만에서는 한 줄로 쌓고 분류는 가로로 넘기는 칩이 된다.

왼쪽 보관함 카드
- "나만 보는 보관함" 표시, 제목 "내활동 다모아", 기록·자료 수
- 저장 공간 막대 (지금 있는 값 그대로 사용)
- 버튼 두 개: 활동 기록하기 / 자료만 올리기
- 분류 목록: "전체" + **기록이 있는 분류만**, 오른쪽에 건수. 맨 아래 "+ 다른 분류 기록하기"
- "사용하지 않는 업로드 정리" (지금 기능 그대로, 위치만 이동)

오른쪽
- 탭: 활동 기록 / 보관 자료 / AI 묶음 요약(준비중 표시, 지금처럼 `ComingSoonButton`)
- 검색창
- 현재 선택 표시 줄: "경력 · 2건" + "전체 보기"
- 활동 기록: 분류별 구역. 구역 제목(분류 이름 + 건수), 흰 카드 안에 줄 단위 목록, 구역 아래 "+ ○○ 추가하기"
- 한 줄 구성: 이름(굵게), 기간 · 첨부 수, 설명 2줄, 오른쪽에 첨부 미리보기(사진/PDF, 여러 개면 +n)
- 기간이 비어 있으면 "기간을 적어 주세요" (주황 글씨)
- 보관 자료: 전체/사진/문서 칩 + 격자(휴대폰 2칸, 그 이상 3칸). 파일 이름과 어느 기록의 자료인지 표시

없앤 것
- 상단 큰 머리말과 곡선 그림, "MY ACTIVITY COLLECTION" 영문 문구
- "어떤 경험을 모아볼까요?" 구역 (왼쪽 분류와 "추가하기" 버튼이 대신함)
- 분류 드롭다운 필터 (왼쪽 분류 목록이 대신함)

그대로 둘 것 (시안에 그리지 않았지만 기능 유지)

### 4-3. 작성창 (`damoa-form-mock.html`)

배치: 왼쪽 미리보기 카드 + 오른쪽 작성 영역. 아래에 저장 막대 고정.

- 제목: "경력 기록하기" (분류에 따라 바뀜)
- 분류 버튼 줄: 경력 / 학력 / 자격·면허 / 교육·연수 / 다른 활동
- 흰 종이 한 장 안에 질문 네 개, 얇은 선으로 구분

| 순서 | 경력일 때 질문 | 칸 |
|---|---|---|
| 1 | 어디서 일했나요? | 근무지 이름*, 직무·직책* |
| 2 | 언제 일했나요? | 시작 연·월*, 종료 연·월* 또는 "지금 재직 중이에요" |
| 3 | 어떤 일을 했나요? (선택) | 근무 형태(누르기), 담당 업무(여러 줄), 근무지 위치(재직 중일 때만) |
| 4 | 증빙 자료가 있나요? (선택) | 사진·PDF 올리기 |
| 끝 | 더 적기 (접힘) | 부서, 배운 점·성과, 관련 링크, 개인 메모 |

동작
- `*` 네 칸을 채워야 저장 버튼이 켜진다. 저장 막대와 미리보기에 "남은 칸: …"을 보여 준다.
- "재직 중"을 누르면 종료 칸이 잠기고 종료는 "현재"가 된다.
- 시작·종료가 정해지면 "근무 기간 7년 9개월"을 계산해 보여 준다 (양쪽 달 포함).
- 종료가 시작보다 빠르면 경고하고 저장을 막는다.
- 왼쪽 미리보기는 입력하는 대로 바뀐다. 모양은 프로필 이력의 타임라인과 같다.
- "재직 중"은 여러 기록에 동시에 켤 수 있어야 한다 (겸직).

분류별 칸

| 분류 | 제목 칸* | 두 번째 칸* | 기간 | 누르기 선택 | 여러 줄 칸 |
|---|---|---|---|---|---|
| 경력 | 근무지 이름 | 직무·직책 | 시작~종료, 재직 중 | 근무 형태: 정규직/계약직/파트타임/프리랜서/대표·운영 | 담당 업무 |
| 학력 | 학교 이름 | 학과·전공 | 시작~종료, 재학 중 | 상태: 졸업/수료/재학/휴학/중퇴 | 내용 |
| 자격·면허 | 자격·면허 이름 | 발급 기관 | 취득 연·월 하나 | 상태: 취득/갱신/만료 | 내용 |
| 교육·연수 | 과정 이름 | 교육 기관 | 시작~종료, 수강 중 | 상태: 수료/참여/진행 중 | 배운 내용 |
| 그 밖의 13개 | 활동 이름 | 주관한 곳 | 시작~종료, 진행 중 | 없음 | 짧은 기록 |

질문 문구, 예시 문구, "더 적기" 항목은 `damoa-form-mock.html`의 `C` 설정에 분류별로 적혀 있다. 그대로 옮긴다.

## 5. 지금 코드 (확인한 사실)

- 화면: `app/my/damoa/DamoaWorkspace.tsx` 한 파일 (목록 + 작성 dialog). 993줄.
- 분류: `lib/damoa/categories.ts`의 `CATEGORIES` 18개. 각 분류에 `group`(묶음 이름)과 `fields`(세부 칸 이름)가 있다.
- 기록 형식 `Activity`: `category, title, period, description, learning, link, memo, details, files`.
  - `period`는 자유 글자(최대 100자).
  - `details`는 `Record<string, string>`. 분류의 `fields` 이름을 키로 쓴다.
- DB: `damoa_activities.content`(JSONB). 제약은 `title, category, period, description, learning, link, memo`가 문자열일 것, `details`가 객체일 것까지만 본다 (`supabase/migrations/20261029111032_damoa_record_validation.sql`, `20261029110237_damoa_server_storage.sql`). **`details` 안의 키는 DB가 제한하지 않는다.**
- 저장 검사 `validateActivity`: 제목이나 첨부 중 하나는 있어야 함, 분류가 목록에 있어야 함, 링크는 http(s).
- `period`와 `title`을 읽는 다른 곳: `app/my/profiles/ProfileVersionManager.tsx:169` (프로필 이력에 다모아 기록을 가져올 때 `activity.title`, `activity.period`를 그대로 씀).
- `CATEGORIES`를 쓰는 곳: `DamoaWorkspace.tsx`, `ProfileVersionManager.tsx`, `tests/damoa-preview.test.ts`, `tests/damoa-server-store.test.ts`.

## 6. 구현 범위

### 가. DB 변경 없이 하는 부분 (먼저 진행)

1. 보관함 화면 배치 변경 (4-1). 데이터·API는 그대로.
2. 분류 고르기 창 변경 (4-2).
3. 화면에서 묶음 이름 표시 제거. `CATEGORIES`의 `group` 값 자체는 지우지 않아도 된다. 다른 곳에서 쓰는지 확인하고 판단한다.
4. 작성창을 분류별 구성으로 변경 (4-3). 저장은 **지금 형식 그대로** 한다. 아래 대응표를 쓴다.

| 시안의 칸 | 저장 위치 |
|---|---|
| 제목 칸 (근무지 이름, 학교 이름 등) | `title` |
| 두 번째 칸 (직무·직책, 학과·전공 등) | `details`의 기존 키 (경력: "직무·직책", 학력: "학과·전공", 자격: "발급 기관", 교육: "교육 기관") |
| 여러 줄 칸 (담당 업무, 배운 내용 등) | `description` |
| 누르기 선택 (근무 형태, 상태) | `details`의 기존 키 ("근무 형태", "재학·휴학·수료·졸업 상태", "취득·갱신 상태", "참여·수료 상태") |
| 시작·종료·진행 중 | `details`에 새 키로 저장 + `period`에 사람이 읽는 글자를 같이 채움 (예: "2019. 03. – 현재") |
| 더 적기 항목 | `details`의 기존 키, `learning`, `link`, `memo` |

겹치는 기존 키: 경력의 "기관·회사명", 학력의 "학교명"은 이제 `title`과 같은 뜻이다. 새로 저장할 때는 `title`만 쓰고, 옛 기록에 이 키 값이 있으면 지우지 말고 둔다. 자격의 "취득일" 키도 같은 식으로 새 날짜 키와 겹치니 둘 중 하나로 정한다.

`period`를 계속 채우는 이유: 프로필 이력과 목록이 `period` 글자를 그대로 읽는다. 이렇게 하면 읽는 쪽을 고치지 않아도 된다.

기존 기록 처리
- 새 날짜 키가 없는 기록(옛 기록)을 열면 날짜 칸은 비워 두고, 옛 `period` 글자를 칸 위에 "전에 적은 기간: 2019–현재"로 보여 준다. 사용자가 새로 고르면 그때 바뀐다.
- 옛 기록을 자동으로 변환하지 않는다. 자유 글자라 틀릴 수 있다.
- 경력의 옛 기록은 `title`에 "△△병원 물리치료사"처럼 근무지와 직무가 같이 적혀 있을 수 있다. 그대로 두고 사용자가 고치게 한다.

지켜야 할 것
- 제목 없이 자료만 올리는 흐름("자료만 올리기")은 유지한다. 이때는 필수 네 칸 검사를 하지 않고 지금 규칙(제목이나 첨부 중 하나)을 따른다.
- 필수 검사는 화면에서만 추가한다. 서버의 `validateActivity`를 더 엄하게 바꾸면 옛 기록 수정이 막힐 수 있다. 바꾸려면 대표님 확인을 받는다.
- `details`에 넣는 새 키 이름은 한 곳(`lib/damoa/categories.ts`)에 상수로 둔다.
- 새 키 이름과 날짜 글자 형식(예: `2019-03`)은 구현 전에 정해서 현황판에 적는다. 나중에 지도·정렬 기능이 이 값을 읽는다.

### 나. 대표님 승인이 필요한 부분 (승인 전 시작 금지)

1. 날짜를 `details`가 아니라 별도 열이나 정식 필드로 옮기는 일, 또는 DB 제약 추가. 마이그레이션이 필요하다.
2. 기록을 날짜순으로 정렬하는 일. 가의 값으로 화면에서 정렬할 수는 있지만, 옛 기록이 섞이면 순서가 어색하다. 방식 확인 필요.
3. 분류 통합·삭제·이름 변경 (예: 스터디와 동아리 합치기). 기존 기록의 `category` 값을 옮겨야 한다.
4. 분류 표시 순서 변경. 데이터는 안 바뀌지만 프로필 쪽 표시에도 영향이 있는지 확인이 필요하다.
5. 근무지 위치(지도) 연결. `feat/workplace-naver-map` 브랜치의 지도 작업과 묶인다.
6. 증빙 자료로 인증 표시를 주는 흐름. 인증·공개 범위에 닿는다.

## 7. 하지 말 것

- 시안의 예시 기록을 운영 화면이나 DB에 넣지 않는다.

- main에 직접 올리지 않는다.

## 8. 대표님께 확인할 것

1. 분류 순서. 권장: 경력 → 학력 → 자격·면허 → 교육·연수 → 나머지.
2. 분류 18개를 줄일지. 줄이면 6장 나-3에 해당한다.
3. 분류 버튼의 그림 문자(Tossface)를 쓸지.
4. 봉사·강의처럼 하루짜리 활동은 "일"까지 받을지. 시안은 연·월만 받는다.
5. 필수 네 칸이 과한지. 특히 "두 번째 칸"(직무, 학과, 발급 기관)을 필수로 둘지.
6. 작성창을 지금처럼 뜨는 창(dialog)으로 둘지, 시안처럼 한 화면으로 열지. 시안은 한 화면 기준으로 그렸다. 권장: 한 화면. 미리보기 카드를 둘 자리가 생긴다.
