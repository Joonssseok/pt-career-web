## 3. 사용자가 정한 것 (2026-11-18)

1. 프로필 작성을 더 간편하게 한다. 쓰는 사람이 편한 템플릿을 준다.
2. 소개와 상세소개는 네이버 블로그 글쓰기처럼 편한 도구로 쓴다. 사진 넣기와 HTML 쓰기를 포함한다.
3. 이 시안의 구성을 기준으로 인계한다.

아래는 사용자가 아직 확정하지 않았고 Claude가 권한 내용이다. 구현 전에 사용자에게 확인한다.

- 글자색·글자 크기 자유 변경은 막는다.
- 유튜브는 HTML이 아니라 주소 붙여넣기로 넣는다.
- 4단계는 고르기만 하고, 새 기록 추가는 다모아로 보낸다.

## 4. 화면 구조

### 4-1. 전체 틀

- 프로필 템플릿과 같은 2단 구조. 왼쪽 320px 카드, 오른쪽 작성 영역(최대 660px).
- **왼쪽 카드는 실시간 미리보기**다. 맨 위에 초록 점과 "방문자에게 이렇게 보여요". 사진·이름·직군·한 줄 소개·전문 분야가 입력과 동시에 바뀐다. 아래 "전체 미리보기" 버튼은 새 프로필 템플릿 전체 화면을 연다.
- 오른쪽 위는 단계 탭. 번호 동그라미 + 이름. 현재 단계는 진한 동그라미, 지난 단계는 연파랑 동그라미.
- 단계는 순서대로만 가는 것이 아니다. 탭을 눌러 어느 단계로든 바로 갈 수 있다.
- 아래 고정 줄: 왼쪽 "이전", 가운데 "자동 저장됨 · 방금", 오른쪽 "다음". 1단계에서는 이전을, 5단계에서는 다음을 숨긴다.
- 휴대폰에서는 미리보기 카드가 작성 영역을 밀어내지 않게 한다. 시안은 카드가 위에 그대로 쌓여 있으니, 구현에서는 카드를 접어 두고 "미리보기" 버튼으로 펼치게 한다.

### 4-2. 단계별 내용

**1단계 기본 정보** — "방문자가 가장 먼저 보는 내용이에요. 1분이면 돼요."

| 항목 | 입력 방식 | 비고 |
|---|---|---|
| 프로필 사진 | 사진 + "사진 바꾸기" 버튼 | 기존 업로드 로직과 조건(JPG·PNG·WebP, 5MB) 그대로 |
| 이름 | 한 줄 입력 | |
| 직군 | 눌러서 고르기 | 기존 직군 목록과 선택 개수 규칙을 따른다. 시안은 1개로 그렸다 |
| 한 줄 소개 | 한 줄 입력 + 글자 수 표시 + 예시 문장 | 기존 `headline` |
| 전문 분야 | 눌러서 고르기, 개수 한도 표시 | 기존 목록과 한도를 따른다. 시안은 3개로 그렸다 |

기존 기본 정보에 있는 디자인 선택, 소셜 링크, 추가 링크도 이 단계에 둔다. 시안에는 그리지 않았다. 빼지 않는다.

**2단계 소개** — "홈 화면 맨 위에 크게 보이는 글이에요. 첫 줄이 가장 크게 나와요."
글쓰기 도구 하나. 기존 `introduction`.

**3단계 상세소개** — "수업 방식, 공간, 자주 받는 질문을 사진과 함께 자유롭게 꾸며요. 비워 둬도 공개할 수 있어요."
글쓰기 도구 + 아래에 틀 넣기 버튼 줄. 프로필 템플릿의 "상세정보" 탭에 나오는 내용이다. 새로 저장할 곳이 필요하다(6장).

**4단계 이력 고르기** — "다모아에 모아 둔 기록 중 이 프로필에 보여 줄 것만 골라요. 새 기록은 다모아에서 추가해요."
분류별 묶음(경력, 자격·면허, 교육·연수 …). 묶음마다 "8개 중 8개 선택". 줄마다 제목, 기관, 인증 여부, 오른쪽 체크. 기존 다모아 선택·제외·순서 기능과 같은 데이터를 쓴다. 순서 바꾸기는 기존 방식을 유지한다.

**5단계 공개 전 확인** — "빠진 것이 있어도 공개할 수 있어요. 채울수록 방문자가 믿고 연락해요."
채운 것은 파란 체크, 비운 것은 회색 줄표와 "쓰러 가기" 링크. 아래에 "공개 신청" 버튼과 "신청하면 운영자가 확인한 뒤 공개돼요" 안내. 기존 공개 전 확인·심사 흐름에 연결한다. 공개 조건 자체는 바꾸지 않는다.

### 4-3. 글쓰기 도구

버튼 줄 (왼쪽부터): 제목 · 굵게 · 목록 · 번호 목록 · 인용 | 사진 · 링크 · 구분선 … 오른쪽 끝 HTML

- 버튼은 모두 44px 이상. 좁은 화면에서는 두 줄로 넘어간다.
- **사진**: 버튼으로 파일 고르기, 글 쓰는 곳에 끌어다 놓기 둘 다 된다.
- **링크**: 버튼을 누르면 주소 입력 줄이 펼쳐진다. `http(s)://`로 시작하는 주소만 받는다. 글자를 선택한 상태면 그 글자에 링크를 건다.
- **HTML**: 누르면 같은 자리가 HTML 원문 편집 칸으로 바뀌고 다른 버튼은 흐려진다. 다시 누르면 돌아온다.
- 다른 곳에서 복사해 붙여 넣은 글은 서식을 떼고 글자만 받는다. 블로그나 한글 문서의 서식이 딸려 오지 않게 한다.
- 빈 칸에는 안내 문구가 흐리게 보인다.

**틀 넣기** (상세소개만): 누르면 커서 위치에 소제목과 빈칸이 들어간다.

| 버튼 | 들어가는 내용 |
|---|---|
| + 이런 분께 맞아요 | 소제목 + 목록(예시 한 줄 + 빈 줄) |
| + 수업 진행 순서 | 소제목 + 번호 목록 3줄 |
| + 자주 묻는 질문 | 소제목 + 굵은 질문 + 답 |
| + 수업 장소 안내 | 소제목 + 안내 문단 |

틀 문구는 `profile-editor-mock.html`의 `TPL`에 있다. 그대로 쓴다.

## 5. 지금 코드 상태 (2026-11-18 로컬 main 작업 폴더에서 확인)

이 폴더는 origin/main보다 뒤처져 있고 커밋되지 않은 변경이 있다. 시작 전에 최신 코드에서 다시 확인한다.

- 작성 화면: `app/my/profiles/page.tsx` → `ProfileVersionManager.tsx`. 기본 정보는 `app/expert/edit/EditForm.tsx`(`commonOnly`).
- `headline`은 한 줄 입력(최대 100자), `introduction`은 일반 글상자(최대 5000자)다. **둘 다 서식 없는 글자**로 저장되고 그대로 출력된다.
- 프로젝트에 글쓰기 편집기나 HTML 정리 라이브러리가 **없다**. `dangerouslySetInnerHTML`을 쓰는 곳도 없다.
- 프로필 버전 내용(`VersionContent`)의 키는 SQL에서 허용 목록으로 검사한다(`headline, introduction, sections, activities, order, excluded, activityRegion`). 새 키를 넣으려면 마이그레이션이 필요하다.
- 사진 저장소: `profile-images`(프로필 사진), `profile-gallery`(갤러리). 둘 다 서버 경로(`/api/profile-photo/…`, `/api/profile-gallery/…`)를 거쳐 내려준다.

## 6. 두 부분으로 나눠 진행한다

### 가. 화면만 바꾸는 부분 — DB 변경 없음, 먼저 진행

- 5단계 구조, 단계 탭, 이전/다음, 왼쪽 실시간 미리보기.
- 1단계의 입력 방식(글자 수 표시, 예시 문장, 눌러 고르기).
- 4단계의 묶음별 체크 목록, 5단계의 확인 목록.
- 자동 저장 표시. 기존 초안 저장을 입력이 멈춘 뒤 자동으로 부르고, "저장 중… → 자동 저장됨"을 보여 준다. 저장이 실패하면 "저장하지 못했어요. 다시 시도"를 보여 주고, 실패한 채로 화면을 떠나려 하면 알린다. 실패를 "자동 저장됨"으로 표시하지 않는다.
- 2단계 소개는 이 단계에서는 **기존 일반 글상자를 그대로** 둔다. 도구 버튼 줄은 나 부분에서 붙인다.

### 나. 글쓰기 도구와 상세소개 — 저장 방식이 바뀜, 사용자 승인 뒤 진행

서식 있는 글, 사진, HTML을 저장하려면 저장 형식과 DB가 바뀐다. 프로젝트 규칙상 범위를 정해 사용자 승인을 받은 뒤 진행한다. 승인받을 내용:

1. `introduction`을 서식 있는 글로 저장하는 방식. 기존 글자 그대로인 소개는 깨지지 않아야 한다(줄바꿈을 문단으로 읽기).
2. 상세소개용 새 키를 `VersionContent`에 추가하고 SQL 허용 목록·검증·공개 반영 함수에 넣는 마이그레이션. `activityRegion`을 추가한 `supabase/migrations/20261108085627_profile_activity_region.sql`이 같은 종류의 선례다.
3. 글 속 사진을 올릴 저장소와 접근 규칙. 초안 단계의 사진은 본인만, 공개된 프로필의 사진만 누구나 볼 수 있어야 한다. 기존 갤러리 저장소 규칙을 참고한다.
4. 사진 장수·용량 한도. 사용자가 정해야 한다(9장).

## 7. HTML과 서식 글의 보안 — 반드시 지킬 것

전문가가 쓴 HTML이 공개 페이지에 그대로 나가면 악성 스크립트가 방문자 계정을 가로챌 수 있다. 이 사이트는 로그인 세션과 개인정보를 다루므로 아래를 전부 지킨다.

- **서버에서 허용 목록으로 정리한다.** 저장할 때 반드시 하고, 출력할 때도 다시 한다. 브라우저에서만 정리하는 것은 보호가 아니다.
- 허용 태그: `p, br, h3, b/strong, i/em, ul, ol, li, blockquote, a, img, hr`. 그 밖의 태그는 지운다. `script, style, iframe, object, embed, form, input, link, meta, svg`는 내용까지 지운다.
- 허용 속성: `a`의 `href`(http·https만), `img`의 `src`와 `alt`. `on…`으로 시작하는 속성, `style`, `class`, `id`는 모두 지운다.
- `img`의 `src`는 **우리 저장소 경로만** 허용한다. 외부 주소 사진과 `data:` 주소는 지운다. 외부 사진은 방문자 정보를 밖으로 흘리는 통로가 된다.
- `a`에는 `rel="noopener noreferrer nofollow"`와 새 창 열기를 서버가 붙인다.
- 정리는 검증된 라이브러리를 쓴다. 정규식으로 직접 만들지 않는다. 시안의 `clean()` 함수는 보여 주기용이므로 **운영에 쓰지 않는다.**
- 시안은 `document.execCommand`와 사진을 `data:` 주소로 넣는 방식을 쓴다. 둘 다 시안용이다. 운영에서는 유지보수되는 편집기 라이브러리를 고르고, 사진은 올린 뒤 받은 저장소 경로를 넣는다. 새 라이브러리를 추가할 때는 크기와 관리 상태를 확인하고 사용자에게 알린다.
- 유튜브 등 영상은 `iframe` 허용이 아니라 주소를 받아 서버가 정해진 형태로 바꾸는 방식으로 한다. 이번 범위에서는 넣지 않는다.
- 글 길이 한도를 서버에서도 검사한다.
- 정리 로직에는 테스트를 붙인다. 최소한 스크립트 태그, `onerror` 속성, `javascript:` 링크, 외부 사진 주소가 지워지는지 확인한다.

## 8. 하지 말 것

- 기존 저장 데이터를 일괄 변환하거나 지우지 않는다. 옛 형식의 소개도 그대로 읽혀야 한다.
- 공개 조건, 심사, 인증 판정, 공개 범위를 바꾸지 않는다.
- 가 부분 작업에 DB 변경을 섞지 않는다.
- 운영 DB 마이그레이션, 저장소 권한 변경을 승인 없이 적용하지 않는다.
- main에 직접 커밋·푸시하지 않는다. 사용자가 "메인 반영"이라고 하기 전에는 병합하지 않는다.
- `docs/SECURITY_OPERATING_RULES.md`를 먼저 읽는다.
- 미리보기(Preview) 배포는 운영과 같은 DB를 쓴다. 미리보기에서 실제 프로필로 저장·공개 시험을 하지 않는다.
- 시안의 시험 글과 예시 문구를 운영 데이터에 넣지 않는다.
- 의료 직군의 글이다. 예시 문장과 틀 문구에 효과를 단정하는 표현을 넣지 않는다.

## 9. 사용자에게 물어봐야 하는 것

1. 글 속 사진 한도. 프로필당 몇 장, 한 장 몇 MB까지인지.
2. 글자색·글자 크기 변경을 막아도 되는지. 막는 쪽을 권했다.
3. 4단계에서 새 기록을 바로 추가하게 할지, 다모아로 보낼지. 다모아로 보내는 쪽을 권했다.
4. 휴대폰에서 미리보기 카드를 접어 두는 방식으로 가도 되는지.
