작성: 2026-11-18 KST · 작성자: Claude(디자인 시안 담당) · 받는 사람: 구현 담당(GPT)

이 문서는 사용자가 확정한 프로필 디자인 시안을 실제 서비스에 옮기기 위한 인계서다. 시안은 정적 HTML 한 장이며, 운영 코드는 아직 한 줄도 바꾸지 않았다.

## 1. 한 줄 요약

공개 프로필 화면을 "왼쪽 사람 카드 + 오른쪽 5개 탭(홈·상세정보·이력·게시판·영상) + 개인 페이지 내 검색" 구조로 바꾼다. 같은 템플릿이 마이페이지의 프로필 만들기 미리보기에도 그대로 보여야 한다. 아직 만들지 않은 기능은 화면에 자리만 두고 "추후 구현" 안내를 띄운다.

## 3. 사용자가 정한 것 (2026-11-18)

1. 이 시안의 컨셉(왼쪽 사람 카드, 안개빛 바탕, 부드러운 제목 글꼴)으로 간다.
2. **공통 헤더와 공통 푸터만** 현황판 기준을 그대로 따른다. 나머지는 이 시안을 따른다.
3. 탭 순서: **홈 → 상세정보 → 이력 → 게시판 → 영상**. 처음 열리는 탭은 홈.
4. 홈은 소개·현 근무지·인증 이력 요약·수업 안내를 담는다.
5. 상세정보는 본인이 사진과 글을 올려 꾸미는 화면이다.
6. 게시판은 사진이나 칼럼 글 등을 자유롭게 쓰는 곳이다.
7. 마이페이지에서 프로필을 만들 때의 미리보기도 이 템플릿으로 보여야 한다.
8. 아직 구현되지 않은 기능은 "추후 구현" 안내 메시지를 보여 준다.
9. 구독·유료 서비스는 뒤로 미룬다. 이번 작업에 결제·요금제를 넣지 않는다.

## 4. 화면 구조와 디자인 값

### 4-1. 전체 틀

- 공통 헤더: 기존 `components/SiteHeader.tsx` 그대로 쓴다. 새로 만들지 않는다. (96px, 로고 30/36px·800, 하단 2px 파란 그라데이션)
- 공통 푸터: 기존 공통 푸터 그대로 쓴다.
- 본문: 최대 폭 1080px, 좌우 여백 20px. 900px 이상에서 2단(왼쪽 320px + 오른쪽 나머지, 사이 56px). 그보다 좁으면 1단으로 쌓는다.
- 오른쪽 읽는 영역의 최대 폭은 660px.

### 4-3. 왼쪽 사람 카드

- 흰 카드, 모서리 28px, 안쪽 여백 28px. 900px 이상에서 스크롤해도 헤더 아래(top 124px)에 붙어 따라온다.
- 위에서부터: 프로필 사진(112px, 모서리 32px) → 이름(제목 글꼴 34px) → 대표 직군 → 한 줄 소개(headline) → 구분선 → 지역 / 경력 / 인증 경력 → 전문 분야 칩 → 프로필 즐겨찾기 버튼.
- "인증 경력 N건" 숫자는 **기존 화면이 쓰는 계산을 그대로** 쓴다. 새로 세지 않는다.

### 4-4. 탭과 검색

- 탭 줄: 헤더 바로 아래(top 96px)에 붙는다. 선택된 탭은 굵게 + 아래 2px 선. 탭 높이 46px 이상. 좁은 화면에서는 가로로 밀어 넘긴다.
- 이력·게시판·영상 탭에는 개수를 작게 붙인다. 개수가 0이면 숫자를 붙이지 않는다.
- 검색창: 탭 아래. 안내 문구 "이 전문가의 이력·글·영상에서 찾기 (예: 어깨)".
- 검색 결과: 탭 내용 대신 결과 목록을 보여 준다. 줄마다 어느 탭 것인지 딱지를 붙인다. 누르면 그 탭의 해당 항목으로 이동하고 잠깐 강조한다. 결과가 없으면 "찾는 내용이 없어요. 다른 낱말로 찾아보세요."
- 검색은 서버 요청 없이 이미 화면에 내려온 이 전문가의 데이터 안에서만 찾는다.
- 탭 상태는 주소에 남긴다(예: `?tab=career`). 공유한 링크가 같은 탭으로 열려야 한다.

### 4-5. 탭별 내용

**홈** (`01-home-desktop.jpg`)

| 구역 | 데이터 | 상태 |
|---|---|---|
| 큰 소개 문장 + 이어지는 문장 | `introduction`. 첫 줄을 크게, 나머지 줄을 본문 크기로 | 지금 가능 |
| 지금 일하는 곳 | `experiences` 중 `is_current`인 항목 | 지금 가능. 없으면 구역을 숨긴다 |
| 서류로 확인된 이력 N건 | 자격·면허 / 교육·연수 / 학력 / 협회 활동별 인증 건수 | 지금 가능 |
| 수업 안내 | 저장할 곳이 없음 | **미구현.** 방문자에게는 숨긴다 |

소개 문장의 연파랑 밑줄 강조는 시안에서 손으로 넣은 것이다. 실제 구현에서는 첫 줄 전체에 적용하거나 빼도 된다. 임의로 일부 단어만 고르는 로직은 만들지 않는다.

**상세정보** (`02-detail-desktop.jpg`)
본인이 꾸미는 긴 소개 화면. 대표 사진 → 소제목과 글 → 사진 3장 묶음 → 소제목과 글 → 사진 → 자주 묻는 질문(누르면 펼침). 전부 **미구현**이다. 기존 갤러리 사진(`galleryImages`)과 근무 기관 지도(`WorkplaceMap`)가 있으면 이 탭에 먼저 보여 준다.

**이력** (`03-career-desktop.jpg`)
기존 공개 프로필의 경력·자격·면허·교육·연수·학력·협회 활동을 이 모양으로 다시 그린다. 전부 **지금 가능**하다.

- 구역 제목 오른쪽에 개수("3건 모두 인증", "8건 중 7건 인증").
- 인증된 항목은 글자 "인증완료" 대신 파란 체크 동그라미. 화면 읽기 프로그램용으로 "인증완료" 글자는 숨김 처리해 남긴다. 맨 아래에 체크의 뜻을 한 번 설명한다.
- 경력은 현재 재직이 맨 위(기존 정렬 유지). 현재는 "현 근무지" 진한 알약, 나머지는 "이전". 기간이 공개돼 있으면 기관명 아래에 함께 보여 준다.
- 다모아 활동 구역(`activitySections`)이 있으면 이 탭 아래쪽에 같은 모양으로 넣는다.

**게시판** (`04-board-desktop.jpg`, `08-board-mobile.jpg`)
글과 사진을 자유롭게 올리는 피드. 종류 고르기(전체/글/사진), 글마다 종류 표시·제목·요약·날짜. 전부 **미구현**이다.

**영상** (`05-video-desktop.jpg`)
영상 카드 2열. 전부 **미구현**이다. 다만 기존 `youtube_url`이 있으면 "유튜브 채널 보기" 링크 하나를 이 탭에 보여 준다.

시안에는 그려 넣지 않았지만 지금 공개 프로필에 있는 것들이다. 빼지 않는다.

- 소셜 링크 아이콘(유튜브·인스타·블로그·스레드·카카오)과 추가 링크 → 사람 카드의 전문 분야 아래.

- 커버 이미지(등록된 경우만) → 본문 2단 위에 한 줄로.
- 근무 기관 정보와 지도 → 상세정보 탭 또는 홈의 "지금 일하는 곳" 아래. 근무 기관 데이터 구조는 `WORKPLACE_NAVER_MAP_HANDOFF_2026-11-16.md`(브랜치 `feat/workplace-naver-map`)에서 따로 진행 중이니 그쪽 결정을 따른다.
- 누르는 요소는 모두 44px 이상.

## 5. 어디를 고치나

2026-11-18에 로컬 main 작업 폴더에서 확인한 내용이다. 이 폴더는 origin/main보다 뒤처져 있고 커밋되지 않은 변경이 있으니, 시작 전에 최신 코드에서 다시 확인한다.

- 공개 프로필: `app/experts/[id]/page.tsx` → `components/experts/ExpertProfileView.tsx`
- 마이페이지 미리보기: `app/my/profiles/page.tsx` → `ProfileVersionManager.tsx` → `ProfileVisualReview.tsx` → 같은 `ExpertProfileView`

두 화면이 **같은 컴포넌트**를 쓴다. 따라서 템플릿을 `ExpertProfileView` 한 곳에 구현하면 공개 화면과 미리보기에 함께 반영된다. 미리보기용 화면을 따로 복제하지 않는다.

미리보기가 `ExpertProfileView`에 넘기는 것들을 새 템플릿에서도 그대로 받아야 한다.

- `renderItemActions`: 항목별 편집·제외 버튼. 이력 탭의 각 줄 오른쪽에 자리를 둔다.
- `order` / `onOrderChange`: 구역 순서 바꾸기. 이력 탭 안의 구역 순서에 적용한다.
- `activitySections`: 다모아에서 고른 활동.
- `galleryImages`

미리보기에서는 탭을 눌러 다섯 화면을 모두 볼 수 있어야 한다. 미리보기 오른쪽의 기존 보조 패널(250px)과 새 2단 구조가 함께 들어가 좁아지면, 미리보기 안에서는 1단으로 쌓이게 한다. 뷰포트 폭이 아니라 담긴 영역의 폭을 기준으로 한다(컨테이너 쿼리).

## 6. 아직 없는 기능과 "추후 구현" 안내

기존 `components/ComingSoonButton.tsx`를 재사용한다. 누르면 "준비중인 기능입니다" 창이 뜨는 버튼이다. 새 안내 창을 따로 만들지 않는다.

| 기능 | 방문자가 보는 화면 | 본인이 미리보기에서 보는 화면 |
|---|---|---|
| 프로필 즐겨찾기 | 기존대로 버튼 + 준비중 안내 | 같음 |
| 홈의 수업 안내 | 구역 숨김 | "수업 안내는 추후 추가될 예정이에요" 빈 상자 |
| 상세정보 꾸미기 | 탭 안에 안내 한 줄 | 안내 + "꾸미기" 버튼(준비중 안내) |
| 게시판 글쓰기·목록 | 탭 안에 안내 한 줄 | 안내 + "글쓰기" 버튼(준비중 안내) |
| 영상 등록·목록 | 유튜브 링크가 있으면 링크, 없으면 안내 한 줄 | 안내 + "영상 추가" 버튼(준비중 안내) |

탭 안 안내 문구 (그대로 쓴다):

- 방문자: "아직 준비 중인 공간이에요. 곧 이곳에서 더 많은 이야기를 볼 수 있어요."
- 본인: "이 기능은 추후에 열릴 예정이에요. 열리면 여기에서 바로 올릴 수 있어요."

지킬 점:

- 시안의 "예시" 딱지가 붙은 글·영상·수업 안내·질문 답변은 **전부 가짜 자료**다. 운영 코드, 시드 데이터, DB에 넣지 않는다.
- 미구현 탭을 숨기지 않는다. 탭은 다섯 개 모두 보이고, 내용 자리에 안내가 나온다.
- 검색 대상은 실제 데이터가 있는 것(지금은 이력)만이다. 미구현 탭의 안내 문구는 검색에 걸리지 않게 한다.
- 탭의 개수 표시는 실제 데이터 개수만 쓴다.

## 7. 현황판 기준과 다른 점 (사용자가 승인한 예외)

`docs/SHARED_UI_BASELINE.md`의 프로필 상세 기준과 아래가 다르다. 사용자가 "헤더·푸터만 맞추고 나머지는 이 컨셉으로"라고 정했다.

| 기존 기준 | 새 템플릿 |
|---|---|
| Pretendard·Tossface만 | 제목에 Gowun Dodum 추가 |
| 본문 배경 흰색 | 안개빛 `#F4F6F8` |
| 본문 폭 1240px | 프로필 본문 1080px (공통 프레임 1240px 안에서) |
| 상단 약 180px 요약 카드 + 80px 요약 줄 | 왼쪽 세로 사람 카드 |
| 경력은 타임라인 | 구분선 목록 + 현 근무지/이전 표시 |
| 정보는 흰 카드 | 카드 없이 구분선 |
| 글자 "인증완료" | 파란 체크 + 아래 설명 |

구현하면서 `docs/SHARED_UI_BASELINE.md`에 "프로필 새 템플릿" 항목을 추가하고, 현황판의 프로젝트 기준과 변경 이력에도 같은 내용을 적는다. 예외 범위는 **전문가 프로필 상세와 그 미리보기**뿐이다. 다른 화면의 배경·글꼴·폭은 바꾸지 않는다.

배경색이 공통 프레임(흰색)과 만나는 경계를 어떻게 처리할지는 구현하면서 확인이 필요하다. 시안은 화면 전체가 안개빛이다. 공통 프레임을 건드려야 한다면 프로필 경로에만 적용되게 한다.

## 8. 하지 말 것

- 데이터 조회, 공개 범위, 인증 판정, 정렬, 저장 로직을 바꾸지 않는다. 이번 작업은 화면 표시다.
- DB 구조·권한·마이그레이션을 추가하지 않는다. 상세정보·게시판·영상의 저장 기능은 별도 작업이고, 각각 사용자 승인이 따로 필요하다.
- main에 직접 커밋·푸시하지 않는다. 브랜치와 PR로 진행하고, 사용자가 "메인 반영"이라고 하기 전에는 병합하지 않는다.
- `docs/SECURITY_OPERATING_RULES.md`를 먼저 읽는다. 비밀값을 채팅·로그·Git에 남기지 않는다.
- 미리보기(Preview) 배포와 운영이 같은 DB를 쓴다. 미리보기에서 실제 프로필을 게시·삭제하지 않는다.
- 결제·구독·요금제 관련 화면이나 문구를 넣지 않는다.

## 9. 나중에 기능을 만들 때 미리 알아둘 것

이번 범위는 아니지만 사용자와 이야기한 내용이다.

- 상세정보는 자유 편집기보다 정해진 틀(대표 사진, 소개 글, 사진 묶음, 질문 답변)을 권했다. 사용자 확정은 아직이다.
- 게시판 글 종류(글/사진)는 글쓴이가 고르지 않고 사진 유무로 자동 분류하는 쪽을 권했다. 확정은 아직이다.
- 영상은 유튜브 링크만 붙여 제목·썸네일을 가져오는 방식이면 저장 부담이 없다.
- 사진 업로드는 저장 용량과 연결된다. 사용자가 저장공간 유료화를 구상 중이라 한도 설계와 맞물린다.
- 자유 글쓰기는 의료광고 표현, 타인 사진·저작권 문제가 생길 수 있다. 작성 안내와 신고 경로(기존 "제안·신고")가 필요하다.
- "상세정보"라는 탭 이름은 사용자가 정했다. 바꾸지 않는다.

## 10. 사용자에게 물어봐야 하는 것

1. 휴대폰에서 사람 카드가 첫 화면을 다 차지해 탭이 스크롤해야 보인다(`07-home-mobile.jpg`). 휴대폰에서만 카드를 줄일지. 줄이는 쪽을 권했고 답은 아직 없다.
2. 홈의 수업 안내를 상세정보로 옮길지. 지금은 사용자 지시대로 홈에 둔다.
3. 기간이 공개된 경력에 날짜를 어떤 형식으로 보여 줄지. 시안의 프로필은 기간이 비공개라 날짜가 없다.
